# 实时票务与酒店渠道调研

核对日期：2026-10-16。用户尚未开通供应商账号，本轮先确认渠道，不冒充实时接口已接通，也未注册账号、提交商务咨询或下单。

## 推荐顺序

| 渠道 | 官方已说明的能力 | 接入条件与当前结论 |
|---|---|---|
| **同程商旅 MCP / CLI** | 实时航班、酒店、火车票；供企业智能体调用查询、推荐和政策校验 | 最接近云熙三类需求的一站式候选。官方已宣布开放，但未公开本项目可直接使用的端点、凭证或完整字段；需确认个人项目资格、费用及只读权限。**优先询问此渠道** |
| **同程旅仓 OpenAPI** | 酒店列表、按日期和人数查房型、报价、逐晚库存状态、取消规则；有订单前验证接口 | 已有公开接口文档，需平台分配分销账号和AES密钥。适合先接酒店；官方明确机票暂不对分销商开放，不能据此声称覆盖票务 |
| **Duffel Flights + Stays** | 航班报价及刷新；酒店搜索、房型报价和最终报价确认 | 开发账号可建测试token，生产需激活并核验个人/企业信息；Stays另需申请。可作为国际出行候选，中国境内航线、支付与主体资格仍需实测/确认；没有覆盖中国高铁的证据 |
| **携程商旅开发者平台** | 官方提供企业系统集成、联调入口和生态合作 | 商务备选。当前公开页面不足以证明个人项目能开通原始实时库存API，不能按公开免费服务估计 |
| **12306官方余票网页** | 官方车次、时刻、席别余票查询页面 | 可作为用户核对入口。本轮未查到可供本项目直接申请的公开开发者API契约；网页内部请求或第三方封装不能作为稳定生产API的证明 |

以上排序是基于官方能力范围与本项目需求的判断，不是生产联调结果。同程商旅与同程旅仓是不同接入渠道，不混用其开放范围。

## 已核对的接口细节

- 旅仓：`POST /hotel/detail` 返回实时酒店详情，官方限QPS 5；需要入住/离店日期、hotelId等条件。不能只看产品总状态，还要检查每晚库存状态；多间、儿童、取消条件也会影响可售结果。列表价格不能代替最终验证。
- Duffel：航班报价有过期时间，选择后应刷新；酒店依次搜索、取房价、创建quote确认当前可售。搜索成功不等于锁定房间或机票。
- 同程商旅：已公布MCP、Skills和CLI三种接入方式，但公告没有可供未开户项目直接使用的认证信息；暂不编写猜测端点的适配器。

## 开户前需要确认

1. 个人开发者或个人自用Agent是否可接；是否要求企业主体、最低消费或分销资质。
2. 能否只查实时价格/库存，不开下单、支付权限；查询限额、缓存有效期、数据使用范围和收费方式。
3. 中国境内机票、高铁、国内酒店各自覆盖范围；生产与沙箱如何区分。
4. 官方端点、认证方式、完整schema、报价重验与失效契约；是否支持按日期/人数/房间数查询。

取得访问资格后，接入顺序为“实时查询→报价重验→人工选择→日程统筹”。日程复用`mac_trip_plan`与`mac_agenda_plan`，将去机场/车站、提前到达、入住/退房和原有会议一起预排。查不到库存必须报不可用，不能以网页摘要或模型推测填充。下单、支付、退改签若后续开发，继续逐项人工批准。
