2026-10-19。运行最新源码构建的 CLI、真实 DeepSeek/Laya 和本机工具。对话输入是验收人员编写的场景，模型回复及下表列出的工具操作是真实运行结果；不是用户本人参与的自然对话，也不是模拟工具返回。

本轮在私有隔离数据目录中加载现有完整人格、画像，逐轮恢复会话；不覆盖生产台账。场景包括 53 个聊天回合，以及 5 次单独的 `do` 任务引擎验证。失败和复测均保留，不能把总回合数当作通过数。后台尚未部署本轮修改。

**本轮结论：未全量通过。** 多轮聊天及选定工具链路取得通过结果；任务引擎仍有规划不稳定、额外确认和思考输出预算耗尽的问题。工程测试全绿不能代替这个结论。

任务引擎五次记录分别为：条件工具名导致阻塞；新建文件完成；禁止调用的工具名导致误阻塞（实际已写入并读回）；要求额外覆盖确认而停止；测试输入明确允许覆盖本轮测试文件后，规划响应达到 4096 输出 token 上限，仅返回思考、没有计划正文（`finish_reason=length`），CLI 报错退出。最后一次没有完成更新，没有把它当作网络错误重跑或计入通过；审批及工具证据校验均未关闭。

聊天阶段实际调用涉及 `read_file`、`write_file`、`edit_file`、`now`、`ask_user`、`mac_agenda_plan`、`mac_location`、`mac_weather`、`mac_mail_accounts`、`mac_mail_search`、`mac_mail_read`，以及被审批拦住的 `companion_update`。任务引擎还实际调用 `list_dir`。未测试的工具不计入本轮成功范围。

## 根据失败修复了什么

1. **文件读取的有效范围**：工具描述、目录及操作规则明确要求在本次执行中读取，避免模型把历史读取当成当前写入的许可。文件校验没有放宽。
2. **日程约束和结果解释**：不得为塞下事项擅自减小间隔或扩展可安排时间；区分工具返回的实际安排、原始固定时间、未排入事项和是否真正应用。没有修改排程算法或写入权限。
3. **私有事实的跨轮恢复**：当前进程私有工具结果恢复后不可见。追问新的具体数字时重新观察，不用旧自然语言摘要重建小时天气等精细数据；同一数组必须按相同索引读取。
4. **错误输出与职责一致**：共享工具错误回执原本要求所有模型输出 `BLOCKED:`，覆盖了聊天的自然语言约定。现在由当前调用契约决定格式；任务步骤仍遵守自己的成功/阻塞协议。拒绝执行及审批行为保持。
5. **多轮状态保留**：更正、否定、过期、尚未保存等状态应随事实一起保留，避免后续提炼要点时把它们丢掉。
6. **规划和执行器的约定**：显式点名的工具仍需成功调用证据。提示词要求不为可能跳过的分支单独创建步骤，读后覆盖与必要读取在同一步完成；禁止事项用能力描述，避免“不得调用某工具”仍被名称匹配当作必需调用。未放松执行器的证据校验。这里仍是提示词约定，执行器的纯名称匹配局限没有结构性消除，不能宣称从此所有任务都不会被误阻塞。
7. **操作锁生命周期**：全量回归再次出现 MailReview 释放后无法重开的失败。独立测试证明复制的文件描述符会延长原先依赖关闭释放的锁；改为守卫退出时显式解锁，并同步邮件审理、拟回复及日程调用方。复制描述符复现与互斥保持测试通过。并发测试失败与子进程继承之间是机制推断，不声称做过进程级捕获。
