# 人格表达优先级与验收

用户要求：生成时增强完整人格对语言的影响，减少通用助理口吻，同时保留任务和工具能力。本轮修改源码和隔离验收，未部署、迁移生产台账或推送。

## 调整范围

- 完整人格、画像原文件不改，完整人格仍只加载一次；不复制私人昵称、故事或表达细节到公共提示词、测试及文档。
- 新增短共享正文 `crates/yunxi-bot-core/src/prompts/persona_voice.md`，在Chat/Step操作规范、开机/冒泡/跟进职责及只读校对说明之后强调风格分工：人格主导说话方式，通用规则负责把事情办对。用户当前表达要求、事实、权限和输出协议继续有效。
- 前台校对以完整人格为风格依据，只修实际问题。校对返回合法的无问题结论时，代码保留原稿字节，防止无依据地润色成客服话术。存在合法问题时仍接受修订；格式错误、工具请求、空白或超限正文仍停止，不借失败回退草稿。
- Plan/Options、Laya、记忆提取和邮件对外正文不追加陪伴表达规则。工具注册、参数、审批和核验不变；后台仍走既有生成调用，没有新增模型调用或“人格权重”配置项。

这里的“权重”是提示词职责及表达优先级，不是对模型参数做数值调整。人格日常表达遵守原资料已有的运行边界，角色叙事不证明现实经历或工具授权。

## 复现与工程检查

先加入失败测试：共享入口缺少优先级说明；校对认为无问题，却把有个性的候选换成“感谢您的分享……”的通用话术。修复后均通过。

回归还覆盖完整人格不重复装配、内部规划不叠加表达块、校对无工具且不泄露草稿、合法纠错生效、空白/超限原稿和非法校对格式不能绕过校验。原工具审批与任务核验测试继续通过。

最终 `cargo fmt --all -- --check`、无warning的`cargo build`、`cargo test`和`cargo clippy --all-targets`检查结果记在本地验收目录；全量自动测试1433通过、39项按原设计忽略。涉及外部服务的忽略测试需单独运行，不能把忽略计为通过。

## 真实多轮对照

用同一组五轮输入，分别运行修改前后的真实CLI和DeepSeek，使用原始完整人格与画像的本地隔离副本。每轮恢复同一个测试会话，覆盖：忙碌后的闲聊、没有任务只叫一声、读取合成文件、办完事回到聊天、要求不称昵称且保持安静。允许工具仅限文件读取和目录查找，其他工具全部拒绝；未向真人发消息或通知。

- 修改前5/5、修改后5/5完成；两组均正确读取相同文件，仅一次`read_file`成功执行，没有修改文件或错误选用写入工具。
- 修改后的自然回复能从办事切回日常口吻，并遵守末轮的安静与称呼要求；未把人格发挥当作不执行读取任务的理由。
- 修改前也有自然表达。此小样本不能证明整体风格显著提升；修改后的结果仍有“我在这儿”等较通用、重复的收尾，不能据此宣称人格体验已经完善。确定性改善是无问题原稿不再被校对随意替换，风格质量仍需持续真实聊天观察。

完整对话、模型调用记录、私有副本和日志仅存Git忽略的 `data/acceptance/persona-priority-20261019/`，公开记录不复制私人内容。测试前后另核对生产人格与画像的SHA-256一致。

另显式运行已有忽略测试`live_startup_personality_with_synthetic_tool_facts`：同一组合成时间/天气，分别使用直接短句与舒展生活化两种人格，覆盖08时和23时，真实DeepSeek共4次生成均满足输出契约。只用工具替身，不读取真实定位、不发通知。输出在措辞和详略上有变化，但风格差异不强，不能把4次协议通过解释成4次强人格依从通过；报告保留这一体验限制。

## 未测范围

本轮未切换常驻后台、未发送实际开机/冒泡通知、未做长期自然度统计，也未重测真实邮件发送及票务订单。现有校对调用的延迟仍存在，本次没有再增加一次调用。源代码变化将在后续部署后用于生产新回复，不改写历史聊天或已发送通知。
