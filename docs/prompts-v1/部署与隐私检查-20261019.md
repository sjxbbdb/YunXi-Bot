# 分层提示词与人格表达部署

2026-10-19，用户要求“部署、推送，再主动触发一次”。此前提示词分层、任务证据与预算修复、人格表达优先级均只在源码与隔离数据验收；本记录补充本机部署状态，不改写历史报告。

## 已部署内容

- 分用途提示词、实际工具目录、来源和输出协议；完整人格主导用户可见表达，内部提取和Laya不混入陪伴人格。
- 人格适合日常交流的鲜明语言特点可以自然表达，不一律收敛成礼貌稳重；有合格取材的冒泡不必总问项目进度或邀请求助。私人角色原文及画像未修改，也未复制到公共模板。
- 天气有效证据、同对象结果核验、前台只读校对、无问题原稿保留，以及跨恢复的真实生成请求预算。功能与限制见[四项修复](四项修复实施与验收-20261019.md)及[人格表达验收](人格表达优先级与验收-20261019.md)。
- 开机批次去重、固定周期冒泡和Laya只看近期情境的分工同步进入此发布版。执行门禁、人工审批和通知间隔未放宽。

## 检查与切换

`cargo fmt --all -- --check`、`cargo test`、`cargo clippy --all-targets --locked -- -D warnings`、`cargo build --release --locked`及`git diff --check`通过。默认回归1433通过、39忽略；另外显式执行8个真实DeepSeek冒泡场景，按既定协议/静默断言全部通过。此检查不是人格自然度的量化证明；小样本中的措辞仍可能需要打磨。

新版在launchd只读试启动成功后，停止原daemon并确认没有其他Bot进程写入，再备份旧发布程序、启动配置、人格、画像、台账、邮件状态及相关本地状态。使用正式`memory --upgrade`依次迁移v2→v3→v4，两次迁移各自备份；核对除版本头外的全部历史字节不变。

重新加载原LaunchAgent，保持15秒邮件检查、关闭任务自动推进、启用陪伴和开机问候的原启动参数。新PID及新的收件扫描台账确认后台确已工作；不是仅根据launchd显示running判断。人格与画像SHA-256和部署前一致。无需重建原生助手或电脑组件。

回退时必须先停止所有写入者、归档升级后新增的数据，再成套恢复旧程序和旧状态。不能只降台账头或删除新增事件。备份、迁移输出、发布哈希和验证日志仅保存在本机Git忽略的`data/acceptance/persona-deploy-20261019/`。

## 发布边界

推送前检查实际待提交文件，排除人格、画像、聊天/邮件台账、凭证、模型、运行日志及原始验收资料。研究文档去掉机器用户名和本机绝对路径，外部研究目录仅保留相对参考，不随仓库发布提取的整套原文。保留合成测试身份及明确的占位凭证。

用户要求的再次冒泡将在部署和推送之后单独主动触发，生成和实际通知结果保存在私有验收目录；不把手动样例算作自动时机判断通过。未做长期常驻、真实交易或跨平台重新验收。
