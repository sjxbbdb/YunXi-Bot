# 云熙整套提示词设计 v1

2026-10-19 · 源码接入、分步验收及[本机后台部署](部署与隐私检查-20261019.md)已完成；各阶段报告保留当时的失败和未部署状态。

当前状态与实际测试结果见[接入与验收](接入与验收-20261019.md)、[多轮真实链路验收](多轮真实链路验收-20261019.md)与[任务修复复测](任务链路修复与复测-20261019.md)。下方保留完整设计及接口对应；涉及“未来”“接入时”的说明请结合该记录判断，不能把设计计划当成现状。

本套设计以项目遍历为基础，覆盖 **原14种生成用途、10组决策用途、61项Mac内置工具**及资料装配、运行恢复。后续四项可靠性修复新增了前台最终表达校对，因此当前为15种生成用途；具体边界见[四项修复](四项修复实施与验收-20261019.md)。原01–12保留为用途正文分组，不再用“12类”代表全部运行入口；进展回顾仍是设计复用，不新增后台调用。借鉴Codex的职责划分、来源标记、输出契约和指令有效期，不搬入它的身份、性格或工具名。原始人格与画像保持不变；运行代码已按本设计接入。

**通用提示词负责做什么，完整人格主要决定怎么说。** 不把当前私人性格、昵称、故事写进通用提示词；换人格时不用重写任务规则。当前用户明确提出的表达要求与具体语境应得到尊重。事实、执行权限和输出格式不由人格覆盖。

后续已按用户要求强化这一分工：在表达入口明确人格的风格优先级，并保留校对判定无问题的原稿，防止通用润色抹平个性。见[人格表达优先级与验收](人格表达优先级与验收-20261019.md)。

## 共同表达与装配

[00-expression.md](00-expression.md) 仅供对用户表达的调用复用，不是所有模型都要读的总系统提示词。人格正文保持原文件全文，不用其摘要替代；画像和记忆保持各入口已有的授权取材范围。

推荐沿用现有 `Identity` 和 `PromptLayout`：

```text
面向用户：原有完整 Identity + 00表达共用块 + 本次用途正文
         + 相关且必须在动作前到位的工具规范 + 当前输出协议
动态资料：带来源的用户输入/近期历史/真实工具结果/触发原因

内部调用：本次专项职责 + 对应解析协议 + 有来源的必要资料
Laya：现有 Question 指令/选项 + 有界近期状态
```

这描述组合内容，不要求新增消息角色、配置引擎、模型或依赖。当前后端能接受怎样的消息仍由现有客户端处理。邮件07只复用用户对外身份与偏好，不能把云熙对用户的称呼写给收件人。

人格决定措辞、句式、节奏、称呼使用和表达态度；场景规则提供事实和任务限制。用户此刻要求“正式一点”“别开玩笑”可局部调整表达，无需改人格原文件。任务字段、未知事实、审批拒绝和锁屏隐私继续严格处理。

## 接入时必须一并处理的地方

以下为接入必须覆盖的检查点；本次实现和仍保留的边界见接入记录，不能仅替换一个字符串就宣称生效：

1. `continuity::default_rules` 把一句话优先的风格倾向写入“硬规则”。本次已保留真实权限和诚实规则，移除这种固定表达倾向，避免它覆盖人格及用户希望展开的要求。
2. Chat、Step 的邮件/日程/出行/电脑规范不能随旧总提示词一起删除。第一轮接入保留全部现有操作协议，后续有覆盖测试后再按能力装配。新版01/09不是全部工具细则的替代品。
3. `Intent::system` 仍会给Chat/Step追加邮件写作规范；01、09新增表达共用块时须明确邮件正文用用户对外身份。不要把陪伴风格作用到外发正文。
4. Plan 与 Options 各有 CLI 和 core 两组入口。08列清共同字段和不同约束，接入时同步调用点及对应测试，禁止仅修改其中一份。
5. `agent::SYSTEM_PROMPT` 同时用于一般主动表达与已确认跟进。04不能让普通主动事件伪称“用户已经约好”；以实际输入证据区分。两条调用都要验收。
6. 开机调用当前动态输入是 `time` 与 `weather`，没有把系统开机批次显式送入模型。02保持保守措辞；如要明确说“电脑刚开机”，接入时须传入调度器已核验的触发事实，不能仅凭提示词补造。
7. 开机虽然使用统一 Identity，但当前传的是 `Memory::default()`。不宣称该入口已经取得聊天历史或真实常驻记忆；设计没有扩大其取材范围。
8. 历史摘要本次已改为保留角色、工具调用标识和原消息内容的JSON资料。原文中的时间保留；缺失时间不猜。画像学习已回查台账原话，不能凭传输层 `Role::User` 就把工具图片/上下文当本人陈述。
9. 10只改提议要求，不把候选直接写进画像，也不新增后台画像学习。`profile --learn`和接受流程保持现状。
10. 12是可复用的表达规格，尚无独立调用，不创建新定时器。上下文中没有记录时说明缺资料；要查最新状态仍由主对话经已有工具取材。

人格原文中的角色叙事、虚构经历和权限叙述仍按现有人格封装及ADR D159处理。不能把风格主导解释成覆盖现实事实或执行边界。

## 输入和生命周期

- 人格与稳定职责不混入每轮时间、天气或任务ID；动态资料独立提供，沿用前缀缓存机制。
- 用户新消息、系统开机、随机冒泡、确认跟进和工具结果明确区分。补入记忆、摘要或角色资料本身不触发回应。
- 每次调用只选一个主要用途。上一轮的通知长度、JSON格式或静默标记不自动延续到下一种用途。
- 内部提取或审理失败不伪装成“没有事项”；程序保留现有拒绝、降级和审计。提示词不能替代解析器。
- 初次D164接入保持温度、思考模式和工具供给；后续D166独立校对使用思考模式、温度0，无工具。普通生成和后台调用维持原配置，测试需区分两者。
