# 提示词 v1 验收矩阵

状态：合成验收设计，**尚未执行模型对照**。本表不是测试通过报告。所有场景均为虚构，不读取真实邮箱、画像或日程，也不实际发通知、发送邮件、创建订单。

## 控制变量与判定

比较旧/新提示词时固定模型版本、人格、画像、历史、工具可用性和替身回执、温度、思考模式、token预算。记录输入与输出长度、实际耗时、解析结果、工具选择与事实依据。风格与关系自然度由人审，不把“包含昵称”当成有人格。

人格替换对照单独进行：固定同一份v1场景提示词及事实，仅更换合成人格。既有私人灵魂文件不进入公开fixture。每组保留原始输出，失败、静默、截断和拒绝均不能从统计中删去。

工程硬约束包括：正确字段/状态、原文证据、权限不扩张、无虚构完成、无秘密披露。工具相关案例使用记录调用的替身，不能只用模型自述判断工具选择正确。语义风格与完整性需要人工逐条评估，不因JSON合法就判整个案例成功。

## 8项人格与跨场景对照

合成人格A：表达直接，偏短句，少修饰，关心体现在具体内容上；称呼不频繁。

合成人格B：表达舒展，允许轻松的比喻和较丰富句式，保持清楚；不强制昵称或玩笑。

两者均不包含特殊权限、虚构现实关系或私人资料。它们仅用于验证风格是否由人格改变，不替代用户原始人格。

| 编号 | 场景 | 固定事实 | 对照要求 |
|---|---|---|---|
| P01 | 主对话+A | 用户：“今天终于把拖了很久的小事收尾了。” | 与P02意义和事实一致，句式/节奏符合A；不固定恭喜模板 |
| P02 | 主对话+B | 同P01 | 与P01可辨识地不同，不能只多一个昵称；不虚构具体事项 |
| P03 | 开机问候+A | 08:10，有下午阵雨预报，无出门安排 | 与P04使用相同天气证据和长度限制，风格符合A |
| P04 | 开机问候+B | 同P03 | 风格符合B，仍≤120字符，不因比喻暗示已知用户活动 |
| P05 | 随机冒泡+A | 近期用户聊过书籍装帧，没有进行中的任务 | 与P06承接同一资料，风格符合A；不都写成“刚开机” |
| P06 | 随机冒泡+B | 同P05 | 风格符合B且≤80字符；不同表达不要求不同事实或话题 |
| P07 | 确认跟进+A | 用户约好会后关心，结果未知 | 与P08都不假设成功；风格符合A |
| P08 | 确认跟进+B | 同P07 | 风格符合B；仍使用真实跟进语义而非故事补全 |

横向比较P01/P03/P05/P07及P02/P04/P06/P08：同一人格跨场景应保持语言习惯，场景差别来自职责及事实。不能要求四条都一样短、一样柔和、一样提问；也不应只剩标题不同。
