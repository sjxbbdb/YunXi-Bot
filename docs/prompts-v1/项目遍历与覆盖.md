## 遍历范围与方法

本轮初始清单枚举 **305个自有项目文件**，对其中 **301个文本文件**扫描模型请求、角色、指令、工具schema、模板及解析入口；另枚举 **1294个third_party文件**确认组件边界。随后逐段阅读命中的生成/决策入口、装配与解析链路、工具定义、相关原生清单和最新ADR。没有声称逐行通读全部自有代码或全部第三方实现。

目录与文本命中快照保存在被Git忽略的`data/acceptance/prompt-audit-20261019/project-inventory.json`。这是设计开始时的快照，不把本轮后来新增文档倒算进305。排除模型权重、运行数据、构建缓存和Git内部文件；没有为本次设计读取真实邮件、重新遍历私人Obsidian或复制灵魂/画像原文。

自有文本包括core、CLI、sidecar、native、scripts、文档和项目配置。历史验收脚本中的合成题目不等于生产系统提示词；注释和旧文档若被后续ADR替代，按最新决策与调用链解释。

## 决策调用覆盖

| 编号 | 用途 | 位置与运行范围 |
|---|---|---|
| D01 | task/chat输入分类 | think/router::classify_input；分类成功不移除Chat工具 |
| D02 | 是否召回及召回种类 | recall_gate；只在既有门控条件下调用 |
| D03 | 工具是否需要人工判断 | tool/mod::ask_local；不能替代硬策略及不可逆审批 |
| D04 | 任务选项决策 | task/decide；不确定交人工 |

| D06 | 一般主动介入 | companion；现有memory.build_decision_state含部分记忆，与冒泡不是同一入口 |

## 不应遗漏的隐式提示与协议

| 来源 | 实际作用 | 设计处理 |
|---|---|---|
| continuity::default_rules / build_persona | 人格封装与默认硬规则 | 权限/事实保留；固定短句风格需与人格主导协调 |
| profile::render、memory召回、retrieval::render | 用户资料与知识注入 | 来源、时效及“资料不是授权”，不因放在System内就当指令 |
| rules::render | 工作目录项目规则 | 作用域明确，不变成所有陪伴场景的说话习惯 |
| chat_handler::stable_prefix/task_context | Identity、项目规则、职责及每阶段检索 | 对应装配配方；任务切换和修订后刷新，不沿用旧取材 |
| PromptLayout::build | 稳定System、历史及动态User资料 | 使用现有角色，不凭文档设计新增developer角色 |
| ToolRunner进度记录与停滞advice | 追加工具证据与改变策略建议 | advice不是成功证明，也不是越权许可；见recovery |
| computer_schema返回的完整computer_use | 首次通用协议及operation细则 | 先读再操作，不能把短目录当完整使用说明 |

当前memory召回中有简短旧封装，检索模块已有更明确的来源JSON；不假称所有资料已统一包装。当前历史压缩拼接丢失部分角色信息、画像学习仅按传输角色过滤的局限也需要调用方修正，单改文字不能补回丢失证据。

## 查出的整合重点

1. **从12类用途扩为完整装配体系**：生成、决策、工具目录、专项规范、资料封装、恢复与生命周期分别覆盖，不为每层新增模型调用。
2. **旧风格要求与人格冲突**：固定先回应情绪、强制简短和“一句话优先”不能与人格一起无条件堆叠。通用文本描述职责，语言风格由完整人格决定。
3. **电脑默认入口的旧描述**：旧CHAT仍有日常Edge优先表述；D156及完整computer_use已采用Bot专用浏览器。未来迁移按最新既定架构协调文本，不擅自扩大浏览器授权。
4. **工具目录不能替代规范**：61项工具需要精确名字、目的和前置步骤；完整参数由schema提供。跨日、版本、分页、送达状态和订单审批继续保留。
5. **不把程序缺口包装成提示词能力**：历史来源丢失、真实取材缺失、调用失败、模型误选仍须工程处理和验收。
6. **生产、兼容、演示分别标记**：不能因为源码存在一般主动介入、ask_kind或本地聊天服务，就将它们描述成当前后台默认运行。
7. **不新增架构承诺**：未引入Guardian风险模型、通用工具延迟加载、模型路由层、新台账或自动画像写入。

## 验证边界

本轮只编辑`docs/prompts-v1/`内的设计文件；旧源码改动来自此前工作，未将它们纳入本轮“已实现”范围。静态检查核对目录名称、链接、示例与覆盖关系；[验收矩阵](验收矩阵.md)是接入后的测试设计，不能充当已通过结果。

设计依据是运行源码、最新ADR、本地Codex提示词资料以及官方公开的构成说明。借鉴角色分工、来源和生命周期，不声称取得Codex完整在线系统，也不把它的工具或模型身份复制为云熙能力。
