# 运行时补充、恢复与结果协议

设计动态说明，不新增模型调用。与01/09配合，不能把故障处理、审批状态机或通知重试改成纯提示词。

| 来源 | 现有处理 | 设计要求 |
|---|---|---|
| tool/progress.rs | 观察停滞达到条件时，ToolRunner追加system提示；来源摘录为user数据 | 仅当前循环注入；停滞不证明失败 |
| 工具回灌 | assistant tool_calls与tool_call_id结果成对保存 | 错误/拒绝/部分结果不能压成成功 |
| computer私有观察 | 当前快照和图片在内存，交还控制时退休 | 恢复后重新观察，不复活旧ref |
| chat的ask_user | 待回答并结束本轮，同批依赖动作停止 | 等真实回答，不续写用户答案 |
| task的ask_user | 同步问答入口 | 拿到答案才推进，信息回答不替代批准 |
| think/session | 当前前缀替换旧前缀，保留相容历史；撤回另有清理 | 模板更新核对实际请求，不只改磁盘 |
| 预算与重试 | 有界执行器负责 | 模型请求重试与副作用重试分开 |

## 停滞时的候选正文

```text
本轮对同一或交替观察范围多次读取，尚未取得新的有效进展。这不证明先前动作失败，也不证明任务已经完成。先核对本轮实际回执、已验证的来源摘录和剩余目标；只为明确缺少的条件继续观察。已取得的信息不因切换窗口作废，当前控件引用则必须重新取得。
如果用户要求的结果已被实际核验，结束并说明结果。若缺少独立核验能力，说明已做到哪一步和未验证部分。需要用户选择时使用ask_user交还控制；不要循环读取、盲关弹窗或重复可能已经发生的发送/提交。此提示不提供新的权限。
```

替换Progress::advice时只保留一份正文，不与旧提示重复注入。触发次数、证据上限及生命周期保持现状。

## 结果语义

| 实际证据 | 可以说什么 | 不能说什么 |
|---|---|---|
| 生成文字或方案 | 已拟好/预排 | 已保存、发送 |
| 请求接受或动作派发 | 已提交，尚待核验 | 业务完成 |
| Mail handed_off | Mail接受发送请求 | 收件人收到/已读 |
| 通知confirmed | 通知中心回读匹配 | 横幅一定出现/用户已看过 |
| computer_verify matched | 指定条件在当前观察匹配 | 全任务完成、文件落盘 |
| 待支付订单 | 已有待支付订单及实际回执 | 付款/出票/入住确认 |
| 日程applied及回读 | 系统安排保存 | 现实活动已发生 |
| 部分成功/超时未知 | 已核实与尚待查明的部分 | 全失败、可安全重做 |

用于自然语言，**不是新返回枚举**。Step仍用OK/BLOCKED，邮件用原字段，解析错误不能被模型解释成成功。

没有新增独立格式修复、风险裁决或无限反思模型。解析失败沿用现有处理；自动多次重调、扩大预算或由模型审批不属于本设计。提示词不能单独解决坐标映射、系统权限、服务延迟或计划冲突。

共享工具的拒绝、无人应答和空回答文案只描述事实及下一步，遵循当前调用的输出契约；不强塞步骤专用的BLOCKED前缀到主对话。
