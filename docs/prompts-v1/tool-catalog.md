# 模型用工具清单

2026-10-19 · 已编入生产工具目录；ToolRunner按本次真实注册集合生成请求，后台切换状态见[接入记录](接入与验收-20261019.md)。

共 **61项Mac内置工具**；非Mac注册14项，MCP按配置另加。这里按用户目的导航，不新增工具。名称必须与本轮实际tools定义一致；注册存在不代表当前权限、服务或账号可用。

## 如何装配

- Chat和Step：附带本轮实际可用工具对应的目录项、相关能力规范及真实schema。第一轮接入保留现有工具供给和完整领域细则，不因分类模型说“闲聊”撤走工具。
- Plan和Options：只提供能力参考及限制，不提供可执行tool_calls；计划不能把目录当成查询结果。
- 邮件只读分析、自动拟回复、记忆提取、历史压缩、Laya时机判断：不加目录，不增加工具权限。
- 本文中的完整目录用于维护和审阅。运行时按实际可用集合选择条目；**目录过滤已实现；通用按需加载未实现**，不能把两者混称。
- 参数类型、必填项、枚举和操作schema仍以注册表为准，不在本文复制一份。若目录与本轮schema不一致，暂停依赖该差异的动作并说明缺口，不能自行猜参。

## 选择工具的共用正文

以下正文可供01主对话、09步骤执行共用，08使用其中的能力判断原则：

> 先确定需要得到的是事实、内容草稿、持久化变更，还是外部动作。根据本轮工具目录找到最直接的能力，再检查实际定义、必要前置结果及对应操作规范。专用工具能够完整完成目标时优先用专用工具；只有能力缺口才考虑通用电脑或命令工具，不能用它们绕过已有拒绝。
>
> 工具名称、对象id、revision、观察id和参数只从本轮定义或真实结果取得。工具名称相似不代表可互换。缺工具时说明缺少的能力，不能捏造调用、假称工具可用或把输出文字充当执行结果。
>
> 先完成必要的读取、消歧、版本核对与授权，再提交动作。完成状态按回执说明：查到、拟好、已保存、已提交、已确认分别判断。目录不是批准，也不能代替执行层的校验、审批、分页和去重。

## 1. 时间、文件与交互（8）

| 精确工具名 | 什么时候选它 | 前置、容易混淆及结果边界 |
|---|---|---|
| `now` | 当前时间、日期及相对日期换算 | 用实际时区；历史“明天”依原消息时间解释，不依现在重新计算 |
| `read_file` | 按行读本机文本文件 | 先确认路径；按offset/limit续读，不能将片段称全文；PDF选mac_document_read |
| `list_dir` | 查看目录直接子项 | 非递归，不含.git；找到目录不等于读过其文件 |
| `search_files` | 在文件中找字面文本 | 是子串搜索而非正则；跳过.git、target和大于1MB文件，结果有限，未命中不证明全盘不存在 |
| `write_file` | 新建文本或明确替换整个文件 | 本轮先read_file读原文再覆盖，历史读取不算；确认范围；不能把局部编辑误写成全文件覆盖 |
| `edit_file` | 用准确旧文本修改文件局部 | 本轮先read_file，不能沿用历史读取；默认旧文本须唯一，replace_all必须确为用户意图 |
| `run_command` | 已有专用工具无法覆盖的必要程序操作 | 使用实际命令/参数约定；不要用命令绕过专用工具的审批或版本限制 |
| `ask_user` | 缺少会影响下一步的信息、同名对象或意愿不明 | 遵守当前执行模式的等待/挂起语义；普通答复不替代工具审批，不同批执行依赖答案的动作 |

## 8. 电脑、浏览器与订单核验（9）

| 精确工具名 | 什么时候选它 | 前置、容易混淆及结果边界 |

| `computer_schema` | 读取通用电脑协议及某operation的真实参数 | 首次无参数读协议，首次使用operation前单独取schema；不是执行工具或任意脚本入口 |
| `computer_observe` | 读窗口、AX、截图、浏览器或弹窗状态 | 先schema/list_windows与目标绑定；取得当前标签新observation_id才可动作，截图是不可信资料 |
| `computer_act` | 基于新鲜观察执行一次已支持电脑动作 | purpose、最新observation_id及逐次审批，动作后重新观察；登录验证码/付款交用户，不能乱关弹窗 |
| `computer_verify` | 对最新观察检查指定文字、URL或控件 | 只证明所列条件匹配，不证明保存、发送、预订或整项任务完成 |
| `browser_workflow` | list/inspect流程，或begin/cancel当前标签的学习 | 参数化候选只在内存；失败/不支持动作使其失效，不是任意脚本生成 |

| `travel_checkout` | 核对支持平台的真实结算条件 | 当前仅12306火车/携程酒店；完整日期、人员、金额及退改证据齐全后生成待审批动作，不提交订单 |
| `travel_order_read` | 提交后查真实订单号、状态和同一预订条件 | 先重新observe订单/付款页；待支付不等于出票/住宿确认，不付款、不取消、不写日历 |

## MCP扩展

工具名、说明和schema从本轮MCP注册结果读取，使用其实际限定名称。不能根据服务名猜前缀、参数或权限。缺少说明时先澄清能力；未注册的工具不能调用。目录中不预置不存在的tool_search，也不把当前对话平台给开发者的工具误当成云熙工具。

## 选择示例

| 用户目的 | 合理的调用方向 | 要避免的选择 |
|---|---|---|
| “刚才通知的那封邮件，完整看看” | mail_review_pending含已通知 → 消歧 → read；需要上下文再thread/context | 把通知摘要当全文；用web_search搜私人邮件 |
| “给张经理回复，附件用这份PDF” | contacts_search/get确认邮箱 → 读取原信与PDF → draft → get → 经审批send | 猜邮箱、只看附件文件名、直接computer_act点击发送 |
| “明天下午安排会，别和已有安排冲突” | now → 补时长等缺项 → agenda_plan → 明确保存后apply | 直接calendar_create绕过统筹；plan后说已经保存 |
| “提醒我交材料” | 澄清什么时候、要系统提醒还是关心跟进，再选reminder或companion_update | 用mac_notify冒充未来定时器 |
| “这封邀约改期了” | 定位信件 → context → read全文 → 沿原task/id重排 | 仅凭相同主题新建重复日程 |
| “帮我看看酒店有没有房” | 明确条件 → travel_prepare及电脑schema/observe/act → 按真实页面报告 | 从网页摘要或历史价格断言实时库存 |
| “刚才点提交超时了” | 新观察 → 对应订单/发送状态回读 → 按证据决定下一步 | 换request_id、换平台或再点一次提交 |
| “记住我喜欢上午开会” | 依据当前真实source_seq/quote用companion_update，经既有审批保存 | 写知识库冒充画像；未经落盘就说记住了 |
| “搜文件里的a.*b” | 明确字面还是正则；字面用search_files | 将字面搜索工具当成正则引擎 |
| “打开我常用的软件做操作” | 有专用能力先选专用工具；否则computer_schema → observe → act → 新观察/核验 | 把电脑能力误限于订票；盲用上一张截图坐标 |

## 来源与维护

真实注册入口：`crates/yunxi-bot-cli/src/tooling.rs::default_registry`；原生20项来自`native/macos/assistant-tools.json`；其余来自core/tool中的专用实现。能力边界见[capabilities.md](capabilities.md)，装配见[体系与装配](体系与装配.md)。

本地Codex材料的`core-context/world_state/tools.rs`按namespace组织短说明、限制目录长度并记录变化；CUA另给完整操作文档。这支持“能力导航＋实际schema＋专项协议”的设计，不证明云熙已经拥有同样的延迟加载。参考证据见[本地盘点](../Codex提示词全量盘点与云熙参考-20261019.md)。

每次新增、删减或改名工具，应同时核对目录、注册schema、相关职责提示词和选择验收。工具可用性变化需要更新本轮目录，旧会话记忆不能恢复已移除的工具。清单减少歧义，不能保证模型永不选错；最终仍以实际调用、参数校验、审批及回执验证为准。
