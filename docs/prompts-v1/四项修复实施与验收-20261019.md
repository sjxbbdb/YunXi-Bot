# 四项修复实施与验收

2026-10-19。用户批准天气取材、任务结果核验、陪伴表达、真实请求预算四项方案。使用隔离台账与完整人格/画像副本；生产台账、常驻后台及私人原文均未修改。本轮不部署、不推送、不录屏。架构见ADR D166。

## 实现与边界

| 问题 | 当前实现 | 保留的限制 |
|---|---|---|
| 天气数字与确信度漂移 | 校验日期、小时顺序、单位、数组和值域；去坐标；30分钟有效期；恢复后重新查询具体预报 | 格式正确不代表预报必然实现；语言理解仍由模型完成 |
| 陪伴回复偏建议、缺乏倾听 | 共用表达规则尊重当前意图；前台最终草稿增加一次独立只读校对，完整人格仍负责表达 | 增加一次API请求和延迟；仅前台Chat使用；不是所有回复质量的保证 |
| 工具成功被误当目标完成 | 文件完整字节校验及同路径后置回读；日程日期/回执、邮件草稿版本/提交、电脑同目标后置核验 | 不自动证明任意自然语言目标；邮件提交不等于对方收到；真实外部动作本轮未重做 |
| 预算只数引擎推进 | v4台账在每次生成网络尝试前预留，跨恢复累计，未知失败也占额度 | 不是金额上限；不合并Laya、邮件和后台陪伴预算；历史计数不明的旧任务拒绝续跑 |

### 取舍

最初只改共享提示词及摆放位置，真实对话仍出现未经请求的身体建议和无依据的恢复判断；仅让模型读同一上下文再校对也会照抄草稿。这些失败保留在本机验收目录，没有从报告中冒充通过。

最终前台校对独立接收职责规则、完整身份资料、带角色的对话和有效工具证据，启用思考并返回问题标签/最终正文JSON。它没有工具权限，无法借校对执行任务；草稿先缓冲，只有合规JSON中的正文才能展示和入会话历史。校对失败、工具请求、截断或轮数不足都停止，不回退未经校对的草稿。普通聊天因此不再逐字展示初稿，网络等待会更明显。

文件错误回执还增加保守处理：最后一次变更失败时，不能沿用更早的成功回读。实际工具循环还补了私有电脑回执的接线：审计继续去掉私有正文，普通动作和脚本内部动作只在本轮结果中保留目标标识、matched和检查布尔值，完成检查不再因私有原文退休而拿不到证据。文件后续成功写入仍须完成同路径回读；邮件、日程、电脑动作结果不明时先检查状态，不自动重放外部动作。浏览器私有目标参数仅在本轮内存核验，不进序列化或Debug日志。

天气返回保持原有forecast.hourly结构，避免破坏开机问候调用方。没有改人格、画像、工具授权或审批词汇，没有新增运行依赖。

## 真实任务验收

使用当前CLI、DeepSeek及真实文件工具；隔离工作目录，61项实际工具目录仍提供给模型，执行仅允许本案例所需文件工具，其他工具拒绝。独立脚本核对完整目录变化、精确路径、最终内容、写后回读及未修改时的mtime。

| 场景 | 结果 | 生成请求数 |
|---|---|---:|
| 读取数量并新建核对文件 | 总数12、算式正确，只改目标，后置回读 | 5 |
| 更新错误旧文件 | 99改为12，算式正确，只改目标，后置回读 | 7 |
| 已经正确的文件 | 核验后保持内容及mtime，无重复写入 | 5 |
| 含条件与禁止运行命令的要求 | 正确写入并回读，无命令调用或多余追问 | 5 |
| 文件不存在分支 | 新建“待补充”，只改目标，后置回读 | 5 |
| 缺单价和折扣规则 | 追问并停止，没有创建结果文件 | 5 |
| 写入授权被拒绝 | 停止，没有修改文件或绕过工具限制 | 3 |

共7/7符合预期，其中5项完成、2项预期阻塞；不是7项都执行成功。每个真实生成请求均有连续预留和结算记录，未超过上限，费用回执均有token用量。后补的失败变更与空对象回执边界由先失败、后通过的确定性测试验证。

## 多轮真实聊天

主验收使用完整私人人格/画像副本、实际CLI和DeepSeek，每轮退出后用同一会话恢复。没有把本次开发聊天伪装为Bot自己的聊天。

- 天气3轮：当前位置明日预报 → 明日15点 → 确认概率含义。前两轮分别实际定位和查询天气，恢复时没有拿历史概述顶替私有原始数据；最后一轮不调用工具，仅说明概率不保证起止时间。回复未暴露坐标或请求URL。
- 陪伴4轮：疲惫闲聊 → 想坐一会儿 → 明确只听不建议 → 结束聊天。最终一轮样本未再给出症状正常/恢复时间的判断，没有执行工具；明确倾听及结束要求得到响应。上一版同样的7轮样本也保留供比较。
- 最终主验收天气每轮27.80/41.45/26.90秒；陪伴13.02/11.97/36.82/7.78秒，包含路由、工具、服务等待及校对。这个样本不能拆出校对单独耗时或宣称性能提升；慢响应是明确取舍。

另做2轮实际ChatHandler→原生定位/天气→DeepSeek→独立校对，单独保存去坐标的原始预报进行数值对照：首轮温度、15点降雨概率与原文精确一致，追问引用的16点概率也一致，两个回复均未把概率解释为确定的降雨起止。该专用验收显式运行通过，默认cargo test仍跳过它。语气自然度属于有限样本判断，不能由自动断言证明所有未来聊天都会符合预期。

## 请求预算和数据迁移

真实CLI任务使用`--budget 2`耗尽两次生成请求后，重新启动`resume --budget 50`，预留仍为2，未再发起生成请求，步骤保持待处理而非失败。最初验收发现预算错误被当作普通失败消耗步骤重试次数，已先复现再修复：额度用尽或计数不可核实立即等待人工，不自动重试；新一轮跨进程实测通过，旧失败记录保留。单元/本地HTTP及SSE测试覆盖本地校验/限流不预留、失败与截断用量、崩溃未结算、重复结算拒绝、并发抢额度、旧任务历史不明及预算元数据不进供应商请求。

隔离CLI迁移v1/v2/v3到v4分别留下3/2/1份相邻版本备份，历史事件字节不变，重复升级不改变结果。新字段不能写入旧版；旧任务不因升级自动获得零起算额度。生产仍为v2，本轮没有停后台或迁移真实台账。

## 最终工程检查

`cargo fmt --all -- --check`、`cargo build`、`cargo test`、`cargo clippy --all-targets -- -D warnings`和`git diff --check`通过；构建无warning。默认测试1430通过、0失败、39忽略。39项不能计作通过，其中本轮新增的真实天气专项已另行显式执行通过，其余专项未全量重跑。最终日志为`build-final4.log`、`tests-final4.log`、`clippy-final4.log`。

覆盖新增请求预算边界、天气失效/恢复、同对象核验、失败写入不能复用旧证据、校对不可派工具/不得提前流出草稿，以及普通/脚本内部电脑回执的实际工具循环接线。失败路径先复现，修复后通过。后续两处预算状态/私有回执修复没有重跑整批成功文件任务，分别用相关确定性回归和真实跨进程预算场景验证；不将较早批次称为同一二进制的全量验收。
