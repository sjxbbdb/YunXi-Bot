# 本地陪伴 T8：观测与 UI

状态：2026-10-24，已实现并验证。

## 目标

让使用者能看到“这一轮为什么这么回答”，而不是只看到一句结果：

- 本轮召回了哪些记忆/知识，来源是什么；
- 本机模型当前状态（未启动 / 加载中 / 已就绪 / 已闲置）；
- 上次记忆整理、上次知识入库；
- 待确认记忆数量。

## 实现

### 1. 本轮召回事件

- `ChatHandler` 新增 `RecallSource` 元数据（kind/id/source/score），每轮开始清空。
- `semantic_chat_context` 与 `companion_knowledge_context` 在召回成功后记录来源；只记录元数据，不把记忆正文送 UI。
- chat-server 在 `reply` 之后发：

```json
{"type":"recall","items":[{"kind":"knowledge","id":"8f16d02932d1f7c8#1","source":"/tmp/知识.md","score":0.85}]}
```

- macOS `ChatService` 解析该事件，在助手回复后追加一条系统小字：
  `本轮召回：知识 · 知识.md · 8f16...`（最多 5 条，来源取末段）。

### 2. 设置窗口的陪伴状态

`capabilities.snapshot.system.companion` 新增：

```json
{
  "local_listening": true,
  "local_model_state": "已就绪",
  "last_memory_at": 1792829325000,
  "last_knowledge_at": 1792829325000,
  "pending_memories": 0
}
```

- 本机模型状态读取 17872 `/health`：`ok` → 已就绪，`idle` → 已闲置（权重已释放），未监听 → 未启动。
- 上次记忆整理取最近 `info_triaged source=companion_memory`；上次知识入库取 `source=companion_knowledge phase=imported`。
- Settings → 系统新增“本机陪伴”分组，显示上述状态与待确认记忆数量。

## 已知限制

- 召回来源仍是系统小字，不是可点击的来源卡片；后续可做详情面板。
- `last_memory_at` 包含 gate_skip 等最后一次记忆处理，不等于“存入了新记忆”的时间。
- 工具调用本身已在台账中，但 UI 尚未把工具结果关联到具体消息。
- 能力快照只在打开设置/刷新时取一次，不是实时推送。
