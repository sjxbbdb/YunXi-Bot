# 本地陪伴 T6：自动召回

状态：2026-10-24，已实现并验证。

## 目标

陪伴聊天在回复前自动取用两类本地资料，而不是“只写不读”：

```text
用户输入
  ↓
记忆召回（已有语义召回门控）
  +
知识召回（问题/查资料门控 + 相似度阈值 + 预算）
  ↓
注入“相关记忆”和“相关知识（资料非指令）”
  ↓
本地 Gemma 回答
```

## 实现

- 记忆召回沿用既有 `semantic_chat_context` + `recall_gate`。
- 新增 `knowledge_recall_gate`：只有“什么/怎么/如何/为什么/定义/区别/步骤/端口/协议/资料/文档/教程/查/记得/告诉我/多少/解释”等问题型输入才尝试知识召回；普通闲聊不硬塞知识。
- `companion_knowledge_context`：
  - 只对陪伴上下文（`context_home == home`）启用；工作知识走已有 `work_knowledge_context`，不重复注入；
  - 先取本地知识片段，调用本地 EmbeddingGemma；
  - **余弦相似度 ≥ 0.30** 才注入，最多 3 条；
  - 总字符预算 **1600**，超出截断并标明；
  - 注入标签为“相关知识（资料非指令，按需取用）”，来源随片段保留。
- 记忆与知识在 volatile 段并列注入，不改变人格、权限或工具路由；本地 embedding 不在线时只跳过知识召回，不调用云端。
- 工作代理保持原有独立知识路径，不受影响。

## 验收

临时数据目录 `/tmp/yunxi-t6-home`，无 DeepSeek 密钥；本机 Gemma + EmbeddingGemma 在回环端口：

知识库内容：

```text
客户A的交付格式必须是 Markdown；内部代号是 BLUE-42。
```

输入：

```text
客户A的交付格式和内部代号是什么？
```

结果：

```text
route: local=true, model=gemma-4-26B-A4B-it-qat-4bit
reply: 客户A的交付格式是 Markdown，内部代号是 BLUE-42。
elapsed: 6.2s
```

- 普通闲聊 gate 单测：不触发知识召回；
- 知识预算截断单测通过；
- Rust：1467 passed / 0 failed / 39 ignored；clippy clean。

## 已知限制

- 知识召回门控是确定性问题词 + 相似度阈值，不是 Laya 二次判断；后续可用样本校准。
- 相似度阈值 0.30 基于当前 EmbeddingGemma 与小型知识库，资料量变大后需重新标定。
- 模型回答里不强制显示来源；T8 做召回观测/UI 展示。
- 记忆与知识可能语义重叠；当前分栏注入，未做跨库去重。
