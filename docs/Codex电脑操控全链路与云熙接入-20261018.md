# Codex 电脑操控全链路与云熙接入

本轮目标：把已安装 Codex 的电脑操控追到可定位的实现、系统接口和运行证据，供云熙独立补强。**目前取得的是打包客户端实现、原生二进制的部分控制流和受控运行样本，不是完整原始源码，也不是已接入云熙。** 云端模型、原生完整算法、所有浏览器后端仍有明确缺口。

后续用户已授权接入；已落地的条件等待、协议续接、失败诊断及云熙自己的实机结果见[接入验证](电脑操控接入补强与真实验证-20261018.md)。本报告保留研究阶段的事实和限制，不把研究样本追认为Bot验收。

本地统一入口：[`full-chain/README.md`](../data/acceptance/codex-cua-rea/full-chain/README.md)。可读JS、原始汇编、证据、合成网页都在Git忽略目录。本文为独立撰写的实现分析，可进入项目文档；未确认开源许可的安装包材料不随产品发布。

## 浏览器调用链

```text
模型选择已公开工具（模型内部不可观察）
  → cua_repl：持久JS绑定
  → @oai/cua：绑定browser/tab，读取当前观察
  → bundled browser-client：命令序列化、API能力限制
  → nodeRepl.rpc('browser', execute / executeWithRecovery)
  → browser-desktop/service：会话、标签归属、权限、命令分发
  ├─ locator：唯一匹配 → 可见/可用 → 滚动/稳定/命中检查
  └─ AX索引：revision/session/tab/document校验 → 当前元素定位
  → CDP或明确的页面程序激活分支
  → 选定backend（本轮追到IAB宿主桥；不能概括全部后端）
  → 监听导航/弹窗等事件，返回动作结果
  → 显式重新观察，校验当前文档，再判断用户要求的后置条件
```

实际文件、函数与字节锚点：`full-chain/browser-chain.md`、`browser-chain-anchors.json`；IAB后续桥接见`backend-path.md`。以下行为直接影响云熙的实现选择：

1. **对象可复用，观察引用不可随意复用。** tab对象保留不代表旧DOM/AX索引跨导航仍有效；以文档、frame/loader、revision校验。
2. **locator与AX不是同一套定位过程。** locator在当前页面重新解析；AX索引依赖观察生成的映射。不能把一条路线的失效规则套到另一条。
3. **没有一个通用点击函数可以保证所有网站成功。** 有CDP输入，也有受条件限制的`.click()`/`.focus()`降级；部分稳定等待和命中异常分支较宽松。云熙仍应坚持未知不执行，并明确输入方式，不能把模拟事件伪称真实硬件输入。
4. **输入需保护焦点。** 逐字输入路径有每字符目标/焦点检查；fill、typeText、pressSequentially的底层不同，应以真实字段回读验收。
5. **事件先订阅再触发。** 导航和filechooser应先建立监听；拿到chooser只证明文件选择阶段，不证明上传完成。
6. **弹窗是独立对象。** JS dialog用dialog ID/type处理，原生sheet要关联父窗口；不能见弹窗就关闭。部分上游特殊处理不是可直接搬用的用户意图策略。
7. **动作返回不是业务成功。** `click`内部有限等待不能取代“已保存”“订单状态”“文件回读”等明确条件。

## Mac 调用链

```text
cua.getApp / App.click / App.getAXState
  → Mac JS wrapper → client.js
  → native-pipe：版本ping、长度帧、JSON-RPC、pending/deadline
  → SkyComputerUseService request handler
  ├─ 观察：应用/窗口 → settling → AX层级/截图 → Skyshot
  └─ 动作：元素或坐标
      → 必要时重取元素与AX树 → 可点击点/窗口焦点
      → AX动作、属性设置，或按PID输入事件
  → JS接收回包
  → 调用方显式getAXState / 截图 → 判断后置条件
```

原生`PerformAction.handle`、`GetSkyshot.handle`分别定位到`0x10015b0cc`、`0x1001638d4`；元素点击→prepareToInteract→refetchElementIfNeeded→必要时refetchTree存在直接分支，已保存定向反汇编。坐标转换有缩放/平移，但其全部来源及跨显示器行为尚未验收。

传输层用4字节little-endian长度和有界JSON帧；请求关联ID、版本、回合元信息和deadline。超时会关闭连接、拒绝未完成等待，**不证明已经派发的动作撤销或没有生效**。串行保证限于对应transport，不能扩大为整机所有操控串行。

公开JS click wrapper丢弃client返回值；有原生returnSkyshot能力也不代表每次公开点击自动给模型新截图。云熙应显式观察。原始接口、直接边和限制见`native-chain.md`、`native-chain-anchors.json`。

## 运行证据改变了哪些判断

原生采样成功：20秒窗口内用Codex操作计算器，界面逐步7→7+→7+3→10；系统sample的镜像UUID与静态目标一致，栈地址对应`AXUIElementPerformAction`和`AXUIElementCopyHierarchy`的调用返回点。这确认服务实际使用辅助功能动作和层级读取，而非只依据截图计算坐标。采样不能给每条请求唯一归因。

浏览器本机合成样本：

- 输入到指定框、保存按钮事件到达，页面event.isTrusted为true；这只描述该样本，不是授权依据。
- 点击保存返回后，AX仍显示“处理中”。等待结果文字才看到“已保存”。因此必须把“派发完成”和“效果核验”分开。
- 两个同名按钮明确返回strict-mode歧义，没有自动选第一个。
- 点击合成confirm弹窗时出现Input.dispatchMouseEvent超时；随后AX读取及关闭标签在focus emulation处超时，getJsDialog却返回空。**空弹窗缓存不是“页面没有弹窗”的证据。** 静态桥接有相关状态清理/缓存路径，但未取得本轮内部CDP trace，不宣称已定位唯一根因。
- 自动清理失败后由用户确认关闭弹窗或标签，本机HTTP服务已停止。未绕过工具对Codex宿主的明确限制，没有录屏。

完整观察记录与限制见`full-chain/runtime-observations.md`，原生交叉验证见`native-runtime-crosscheck.json`。

## 云熙如何吸收这些机制

现有云熙已经有Controller/session、Driver契约、审批、观察lease、精确目标、dialog ID、verify和进度检测，不能再造一套平行执行器。下表是后续补强落点，**不是本轮已实现清单**。

| 落点 | 保留已有实现 | 要补强的最小行为 | 验收 |
| --- | --- | --- | --- |
| `computer/driver.rs` | 固定Driver版本/目录、私有响应、delivery_unknown | 为已审核的失效/歧义/遮挡/焦点丢失分类给可恢复信息；控制连接失效后清除所有旧观察 | 断线时不把未知送达当未执行；迟到回包不污染新会话 |
| `computer/lease.rs` | 动作审批前后精确目标/观察校验 | 与Driver核对文档/窗口变化、坐标映射与焦点身份覆盖；存在缺口才补 | 刷新、窗口移动、遮挡、同名窗口不误点 |
| `computer/workflow.rs` | 当前观察上的有限核验条件 | 一个获批动作之后，有界只读等待目标条件；不顺带放行下一写动作 | 异步保存中间态不算完成；超时转未知/待人 |
| `computer/native.rs`及Driver开源侧 | 父窗口与sheet对应、token动作 | 验证AX重取、输入焦点变化、混合DPI；不足再独立实现 | 旧元素失效、用户输入、不同显示器场景 |
| `tool/progress.rs`、`tool/runner.rs` | 带来源短期取材、历史与当前证据分开 | 子目标一旦验证就推进；不因切窗反复回源；恢复后重新观察 | 跨网页→计算器→文档保存，轮次耗尽算失败 |
| 弹窗恢复 | 类型/ID/父窗口识别和逐动作策略 | 观察不可用与缓存无记录分开；已弹窗动作超时不重放；无法恢复明确交接 | JS confirm、原生sheet、权限弹窗分别验证 |

独立契约应表达：`Observe(target) → 当前观察及引用`；`Act(观察身份,明确目标,动作,已批准范围) → 未派发/已派发/效果未知`；`Verify(新观察,后置条件) → 匹配/不匹配/证据不足`。这是对现有接口的约束梳理，不引入新台账格式、审批词汇或运行时依赖。

优先顺序：先解决跨应用任务的完成收敛与动作后等待，再做弹窗/断线恢复，最后按失败证据补输入与坐标底层。现有最新跨应用Bot实测仍失败，不能用本次Codex成功样本替代。
