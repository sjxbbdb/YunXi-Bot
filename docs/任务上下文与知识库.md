# 任务上下文与本地知识库

2026-10-15。向量模型选型见 [实测报告](向量模型实测.md)。

## 运行方式

保留 EmbeddingGemma 2 文本编码器；768 维，CPU 4 线程、float32，独立服务 `127.0.0.1:17873`。
DeepSeek 负责生成，Laya 仍在本地负责决策。服务离线加载固定版本且校验 SHA256；知识、记忆正文不会写入编码服务日志。
首个需要向量的任务或知识检索自动启动编码器，加载失败明确报错。`YUNXI_BOT_EMBEDDING_ENDPOINT` 可用于指定已管理的回环服务；指定后不会自动替换该服务。

从仓库根目录运行，统一使用与启动器相同的数据目录：

```bash
export YUNXI_BOT_HOME="$PWD/data"
cargo build
target/debug/yunxi-bot knowledge add /完整路径/资料.md
target/debug/yunxi-bot knowledge list
target/debug/yunxi-bot knowledge search "我想查的问题"
target/debug/yunxi-bot do "依据知识库完成摘要，引用片段来源" --provider deepseek
```

`knowledge add` 只导入明确指定的 UTF-8 `.md` / `.txt` 文件副本（每份最多 2 MiB）。源文件改变后要再次导入；不会扫描整块硬盘，也不会自动刷新原文件。
模型的 `knowledge_search` 工具在连续聊天、do/resume、daemon 的目标任务中可用，仍经过现有工具审批层。
导入库属于当前数据目录，跨工作区共享，不能把它当成按项目隔离的资料库；需要隔离时使用不同 `YUNXI_BOT_HOME`。

```bash
target/debug/yunxi-bot knowledge remove <文档ID>  # 删除副本与派生缓存，保留源文件
target/debug/yunxi-bot knowledge reindex          # 清除派生缓存，下次检索重建
target/debug/yunxi-bot memory --forget <记忆ID>   # 遗忘投影并清除记忆向量缓存
```

遗忘不抹除审计台账中的历史记录；已经生成的历史答复也不会被追溯改写。

## 任务如何获得背景

规划、单步执行、方案生成都进入同一个 `ChatHandler::task_context`：

1. 读取当前 `persona.md`、`profile.md`、项目规则和台账中的常驻事实/偏好。
2. 按既有关键词门控判断是否需要动态私人记忆；工作区记忆先按当前目录过滤，再进入编码器。
3. 独立检索记忆、知识两个命名空间，各最多三个片段；向量相似度只是候选排序，不是事实正确概率。
4. 稳定背景进入系统前缀，相关片段以带来源的 JSON 资料进入本阶段输入；前置步骤结果由引擎传入。
5. 换任务或背景/检索资料版本变化时清除旧任务会话；同一任务且资料未变时保留已获得的工具证据。复用同一个 handler 的 daemon 因此不会沿用其他任务的工具历史。
6. 在现有 Route 审计事件中记录任务、阶段、前缀指纹、来源数量、命中 ID 和模型版本，不额外记录私人正文。

文件不可读、台账损坏、索引损坏、编码器超时或身份/维度不符都会阻止该阶段生成和工具执行。
可写台账时记录 `context_unavailable`、`degraded: true` 与原因；台账本身损坏则直接报错，不能承诺将错误写入已损坏的台账。
规划阶段也能转等待人工；修复后 `resume <id> --provider deepseek` 会重新规划。续跑和后续阶段使用最新快照，前缀指纹可用于核对变更。

知识片段不是指令，不授予工具权限；模型从资料中读到“删除文件”等文字也不能绕过审批。
此变更没有增加运行时依赖，没有改变台账事件格式、审批词汇表或 Mac 的隔离级别。

## 存储与边界

- 事实来源：记忆来自台账投影；知识来自 `knowledge/documents/*.json` 导入副本。
- 派生向量：`vectors/memory.json` 与 `vectors/knowledge.json`，按模型版本和完整片段内容校验复用，更新时原子替换；Unix 创建权限为 0600。
- 小型个人库采用有界精确扫描，最多 8192 个片段且单份缓存最多 32 MiB；触及任一限制报错。不是 SQLite、HNSW 或大型向量数据库。
- 每片段 512 字、重叠 64 字；每批最多 8 条。任务查询超出 2000 字时取开头并在上下文审计中标记。没有启用多模态编码器。
- 相似度阈值 0.75 只是本轮合成校准的起点，不能保证所有无答案查询都会拒绝；应结合真实反馈重新校准。
- 聊天原有的私人记忆门控、词面/字符向量融合保持原状；新语义记忆链路目前作用于目标任务。聊天可按连续对话通过 `knowledge_search` 使用新知识库；Laya 的闲聊标签不再撤掉工具，执行仍受审批约束。
- 主动陪伴表达与 MCP 的入口差异仍见 [项目概览](项目全貌与接线现状.md)，不能将目标任务的改动宣称为所有入口已统一。
