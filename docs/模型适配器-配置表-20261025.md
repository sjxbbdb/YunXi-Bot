# 模型适配器：配置表与启动校验

状态：2026-10-25。

## 做了什么

- `ModelAdapter` 不再散落维护多个模型别名，陪伴模型集中到 `COMPANION_CHOICES` 表：
  - `gemma` / `gemma4` → Gemma 4 26B-A4B
  - `qwen` / `qwen3.5` → Qwen3.5-9B
- 删除失效的 `qwen38` / `qwen38u` / `uncensored` 别名；对应权重已清理，不能让用户切到不存在的模型。
- `chat_server` 启动时使用 `ModelAdapter::companion_for(home)`：
  - 别名未知 → 启动失败
  - `home/models/<dir>/config.json` 不存在 → 启动失败
  - `model_type` 不匹配（Gemma 需 `gemma4`，Qwen 需 `qwen3_5`）→ 启动失败
  - 没有 safetensors 权重 → 启动失败
- `start_local_model` 的模型名改为从适配器读取，不再复制一份映射。
- 启动脚本同步删除失效别名。

## 当前边界

- 这是**代码内配置表**，不是外部 JSON/UI 模型市场；切换模型仍用环境变量并重启。
- 本地后端只接受已验证的 `gemma4` / `qwen3_5` 架构；其他架构不能靠改别名接进来。
- 云端工作代理仍支持自定义 OpenAI 兼容端点，但未做真实第三方 API 验收。
