# 任务证据与规划恢复修复方案

用户要求修复多轮实测的问题。普通提示词与错误处理修复继续进行；下面两项会改变既有约定，实施前单独确认。用户已于本轮明确批准“允许按方案修复并验证”；以下为获批范围。

## 必需工具与自然语言分离

计划步骤新增可选 `required_tools` 名称数组，明确该步骤完成必须有成功回执的工具。新生成的计划必须提供此字段，纯文本步骤可以是空数组；名称必须属于实际工具注册表，重复、未知或坏类型拒绝。条件性调用、禁止事项仍在 instruction 中表达，不作为无条件成功要求。

执行器对新步骤只核对这一数组，不再从自然语言中的“不得调用”“必要时调用”等句子猜必需工具。缺少成功回执仍阻塞；工具参数、前置读取、动作审批和产物核验继续生效。该清单是最低证据约束，不能独自证明全部自然语言目标已完成。

旧任务缺少该字段时保留 D139 的保守检查，不猜测改写历史计划。已有任务续跑保持原语义；新计划、重启、投影重建均保留明确证据要求。

## 台账兼容

台账从 v2 升至 v3，并提供相邻迁移。旧事件原文保留，不补造 `required_tools`；新版允许读取旧格式，写入新结构前要求显式升级。v1 经既有相邻迁移到 v2，再到 v3。旧程序应拒绝 v3，防止忽略新约束继续执行。

本轮只在隔离台账和副本验证，不升级生产后台。未来部署前停止后台，备份台账、相关状态及可执行文件，核对迁移前后事件和投影；回退必须归档新版数据并成套恢复，不能删除字段强行给旧程序读取。

## 规划截断恢复

明确识别提供方 `finish_reason=length`；保留用量并拒绝执行任何截断工具请求。只有无执行工具的规划阶段允许一次重新规划：仍用相同模型、思考模式、完整人格/画像和原目标，单次输出最多 8192 token，计入任务调用上限；额度不足或再次截断即停止，并记录原因及降级标记。不重放工具动作、不对审批失败重试、不无限加预算。

## 其余修复与验收

规划和执行提示词明确继承用户已给的操作授权，常规且范围明确的编辑交工具层审核，避免模型自行添加无必要的口头批准步骤；不可逆动作仍保留现有独立审批。

先复现否定工具名、条件工具、缺失/失败回执、未知工具、旧任务、截断用量遗漏及重复确认，再修复。真实验收覆盖新建文件、更新已有测试文件、无需更改、读取结果不存在和缺少必要用户信息；独立核对实际文件及调用事件。保留首次失败，不能只报告最后一次通过。

本方案修改 D139、D141/D164 的对应证据、规划恢复与格式约定；不增加运行依赖、不改审批词汇、不修改私人原文、不自动部署。
