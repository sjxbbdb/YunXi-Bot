## 邮件草稿为什么存本机

本机实测发现Mail的富文本附件回读会抛出`-10000`，临时撰写对象也不能作为可靠的持久草稿接口。因此审批的事实来源是云熙本机草稿，保存在`~/Library/Application Support/YunXiBot/native/`，不承诺出现在Mail的“草稿”邮箱。

草稿及回执文件权限0600，目录及附件副本目录0700；附件在起草时复制并计算SHA256，读取、修改、发送前复核。回复保留原邮件定位与版本，发送前再次核对，随后使用Mail的reply接口；转发包含原邮件头、正文与附件副本。

发送前持久保存待定回执并锁定草稿。相同请求编号可重放已确认结果；发送结果未知时，换编号也不能重新发送同一草稿。必须先人工核对发件箱/已发送。读回收件人、发件人、主题和正文一致后才提交发送。

**附件限制**：Mail不支持可靠的发送前附件内容回读。已校验本机副本并检查附件插入调用，但不能证明Mail最终封装内容；带附件的发送回执明确`degraded:true`并附原因。`handed_off`只表示系统接受，`delivered:false`不代表失败，而是没有送达证明。

五组真实模型场景：

1. 通讯录查无此人，如实返回空结果。
2. 读取合成附件，回答文件内随机口令。
3. 查询上海博物馆人民广场馆地址，并调用网页搜索核对开放时间来源。
4. 查询明天会议路线和天气，将实际步行分钟数加用户给出的15分钟准备时间，绑定会议预排；不保存。
5. 两位同名张经理先追问，用户回答“研发那位”后才起草；收件人精确匹配合成邮箱，草稿随后清理。

初始验收另用真实Mail完成新信、回复、转发的发送前组装，以及附件插入检查，当时没有调用真实发送。随后完成了下述经用户明确授权的实发补测。本批初次验收没有搜索到带邮箱的联系人；后续全链路复验已补齐真实有效联系人ID读取。真实同名邮箱消歧仍只使用合成候选。

### 用户授权的真实附件邮件补测

2026-10-16 11:05（北京时间），用户明确指定自己的QQ邮箱和桌面DOCX简历，授权实际发送一封测试邮件。调用项目的`mac_mail_draft`、`mac_mail_draft_get`核对唯一收件人、正文与附件副本后，使用`mac_mail_send`提交；未调用其他发送渠道，也没有重新发送或多发一封。

- 原生起草首次没有返回有效回执，未调用发送；确认未生成草稿后重新起草成功。后续每次操作编号与状态均写入私有验收记录。
- 发送回执为`handed_off`，最初邮件在发件箱，因此当时未宣称发出。随后查询确认同主题邮件只有一封出现在“已发送”，发件箱中已不存在。
- 已发送原始MIME中的DOCX附件大小为44,359字节，SHA256与桌面原文件完全一致，验证了Mail实际封装的附件内容。
- 再通过项目的`mac_mail_read`与`mac_mail_attachment_save`读取并保存已发送邮件附件，字节数及SHA256再次匹配。临时下载副本已清理，桌面原文件未修改。
- 用户随后明确确认“已收到，附件能正常打开”。本次新信从发送、已发送回读、附件字节校验到QQ端接收和打开，完整链路通过。该结果不证明所有邮件都能送达；回复/转发的真实发送仍未进行。

私有证据为`data/benchmarks/tools/mail-send-user-20261016.json`（0600、git忽略），包含具体地址、邮件ID、请求编号及文件摘要；个人邮箱和简历内容不写入本公开报告。发送前附件无法回读的产品限制仍保留：本次是在发送后核实已发送MIME，不能据此移除发送前的降级提示。

## 清理与保留的失败证据

Mail的删除邮箱脚本接口不可用，原生邮件验收报告保留`cleanup:false`和总结果`passed:false`，不能把26项功能检查通过冒充整份报告通过。用户单独批准后，经Mail界面删除了本轮四个导入邮箱和三个归档测试邮箱；重新查询确认七个测试邮箱均不存在。

发送前组装留下的合成草稿已移入废纸篓，本机记录标记删除；没有清空废纸篓，账户远端同步不在验收范围。本机草稿按各自ID丢弃，测试日历/待办已回读确认清理。用户自己的邮件、联系人和日程未作为删除目标。

早期的Mail附件回读失败、单条件搜索错误、Rust参数处理插入额外`attachments:null`、验收脚本误读截短台账，以及将普通文字追问误判为失败的报告均保留。修复后重新验证，未将失败样本改写成成功。

原始证据在git忽略目录`data/benchmarks/tools/round2-*`。含会话/账户信息的报告设为0600，不进入仓库；汇总为`round2-summary-20261016.json`。

## 复验入口与未覆盖范围

```bash
cargo fmt --all -- --check
cargo build
cargo test
cargo clippy --all-targets -- -D warnings
PYTHONPATH=sidecar .venv/bin/python -m unittest sidecar/test_e2e_assistant_tools.py sidecar/test_e2e_builtin_tools.py
./启动.command mac status
# 会创建并清理未来合成日历/待办，需已有系统权限：
cargo test live_ -- --ignored --test-threads=1
# 真实模型使用合成数据，发送被拒绝：
.venv/bin/python sidecar/e2e_assistant_tools.py --out /tmp/assistant-new.json
```

`sidecar/e2e_mail_tools.py --out <新路径>`会导入合成邮箱；Mail脚本无法自动删除邮箱，运行后需在界面按精确名称清理，永久删除需用户确认。不要拿真实邮件运行该验收。

本轮未验证长期常驻、断网恢复后的账户同步、跨设备同步、任意自然表达、真实同名联系人库、回复/转发的实际发送，以及自动送达/退信检测。新信附件实发范围以上述补测为准。后续修复将邮件串改为Mail头部过滤查询，同一账户最多2000个候选、100个引用标识和200个文件夹，18秒查询预算，达到限制会标记不完整；即使未截断，也只覆盖本机已经同步的邮件。不能因此声称读完服务器上全部邮件。天气与ETA会变化，会议时间或地点调整后应重新查询。
