# 第三批工具验收（2026-10-16）

本批范围由用户选择为“出行住宿与多日行程”，常驻长测后置。新增`mac_trip_plan`和`mac_trip_apply`，当前Mac工具注册表共43项。出行/酒店查询继续使用已有地图及网页工具，资料读取继续使用邮件和文档工具，不另接交易平台。使用方式及边界见[出行住宿与多日行程](出行住宿与多日行程.md)。

## 完成内容

- 多日读取、预排和统一批准保存：全部日期预检，逐日版本复核、串行写入及回读。中途失败报告失败日期、已完成日期、未尝试日期，失败当天也可能部分完成。
- 事项可保存预订来源、车次、酒店和地址等`details`，随对应提醒事项保存；旧数据缺省为空，不改变审计台账格式。
- 酒店入住/退房分别安排，准备及通勤关联列车或活动；支持连续修改、取消和跨会话读取。写入沿用既有审批与原生应用，无需重新签名或申请系统权限。
- 修复会话恢复入口：`chat --resume <id>`现在正确选择指定会话，仍支持`--resume --id <id>`；ID冲突或缺失拒绝执行。
- 查询回复要求具体来源链接，价格、库存及退改条件没有实际证据时明确未核实；网页自称“官网”不能被当成已核实的运营方身份。

## 真实链路结果

6个日程/资料场景通过74项检查，公开查询复验通过8项，共**7个场景、82项检查通过**。日程使用合成资料及2031年5月18–19日测试日期；通过真实Laya、DeepSeek、Mac EventKit和已有系统权限完成，非模型/原生接口替身。写入仅在测试进程显式允许，其他工具逐项拒绝。

| 场景 | 实测证据 |
|---|---|
| 信息不全 | 未知目的地和日期时追问，没有编造计划或写入 |
| 读取预订文件、两日预排 | 真实读取虚构列车、酒店及活动资料；5个事项全部排入；准备关联列车；入住/退房各30分钟；未写系统 |
| 下一轮保存两天 | 5条日历记录与5条提醒事项全部回读；准备提醒时间为本地10:20；未执行商家预订 |
| 连续追问改第二天活动 | 14:00改为16:00、时长60分钟不变；原系统ID保留，其他资料与安排保留 |
| 全新会话读取 | 两天安排、原ID、酒店/列车详情可从系统恢复，不依赖原对话记忆 |
| 回到指定会话取消列车 | 列车和关联准备均取消，两个日历块移除，待办记为完成；其他3个日历块保留 |
| 公开交通/酒店查询 | 实际查地点、驾车及公交ETA、博查网页；返回两家酒店名称与地址、具体资料页链接；房价、可订状态和退改条款未核实；不写系统 |

交通比较按用户给定的到达日期时间请求，不能将某次估算当成固定通勤时长。酒店查询验证了工具接线与证据引用，没有核实库存、房价或官网身份。公开来源仍需在真实预订时复核。

## 保留的失败与修正

旧报告没有覆盖或改写：

- 首轮测试只允许文档工具，但模型正确选择了通用文本读取工具，因测试拒绝规则被拦；修正测试允许两种合法读取路径，并核对真实工具正文。
- 两次测试脚本误判：将系统UTC时间按字符串与上海本地时间比较，以及要求活动改期后其时间说明也逐字不变。分别改为按同一时刻比较、区分变化活动与未变预订资料。
- 跨会话实测暴露CLI恢复指定ID失效；先以单元测试复现，再修复入口并重新验证，保留原失败记录。
- 公开查询首次只有平台名称、没有可点击链接，补强回复约束；后续一次脚本只认“价格”而不认“房价”，修正等义词检查，单独复验查询场景。最终人工核对两家酒店均有实际返回来源页，明确标注未核实信息。

私有证据在git忽略目录`data/benchmarks/tools/`，权限0600：日程最终记录`round3-trip-20261016-r6.json`前6场景、公开查询最终记录`round3-research-20261016-r7.json`，构建检查日志`round3-build-test-20261016.log`。`r6`整份报告仍保留当时错误关键词检查导致的失败结果，不冒充整份全绿；最终采用逐场景证据汇总。

原日程回归记录为`round3-agenda-regression-20261016.json`，最终逐场景汇总为`round3-summary-20261016.json`。

各次真实写入的合成日历和提醒事项均已逐条删除并回读确认。临时凭证副本随测试目录清理；用户原凭证及原日程未作为清理目标。
