# 决策模型后训练：首批中文样例审核

> 当前审核入口已更新为 [Laya 项目微调：32个场景](Laya项目微调-审核与方案.md)，覆盖当前 DeepSeek 生成、本地辅助模型架构。以下16条保留为历史草案，仍未审核、未训练。

状态：**16 条合成草案，全部待你审核，尚未用于训练。** 本轮只确认判断标准。所有人物、事件和偏好均为假设，不会写入真实记忆或策略。

## 怎么审核

可以直接在聊天里回复：`全部认可`，或 `M02 改为现在提醒，理由是……；其余认可`。也可以删掉某条、补充判断所需的条件，或说“这条我自己也不确定”，不需要读 JSON。

这里审核的是模型对情景的建议。不可逆动作人工审批、明确的免打扰要求、审批模式和失败降级仍由现有约束层决定，训练结果不能越过它们。

“现在提醒 / 稍后看 / 不提及”沿用现有 `speak / hold / quiet`，不新增运行状态。“不提及”不代表删除、永久屏蔽或改动任务状态。C05–C06 只判断有无明确情绪支持需求。

## 16 条样例

| 编号 | 情景 | 建议判断 | 理由 |
|---|---|---|---|
| C01 | 下午三点，使用者二十分钟没有发消息。后台任务正常，没有新结果、待办期限或新的求助；没有证据表明他遇到了困难。 | **保持安静** | 沉默本身不是需要打扰的证据。 |
| C02 | 下午三点，使用者二十分钟没有发消息。他正在等的构建首次失败，日志明确缺少本机 SDK，重试不能解决，需要他选择安装或暂停；此故障尚未通知。使用者没有要求免打扰。 | **现在说明阻塞** | 出现了新的、阻塞用户目标且需要他决定的事实。 |
| C03 | 使用者请助手在后台跑测试，说“我这半小时专心写代码，结束后告诉我结果”。测试已通过，仍在这半小时内，没有新的问题。 | **留到专注结束** | 结果有用，但使用者已经给出了合适的告知时机。 |
| C04 | 使用者请助手在后台跑测试，说“我这半小时专心写代码，结束后告诉我结果”。测试已通过，约定的半小时已经结束，结果尚未告知。 | **现在告知结果** | 约定的告知时机已到，结果尚未重复发送。 |
| C05 | 使用者一小时没有说话；没有情绪表达或求助，任务正常进行。 | **没有明确支持需求** | 不能仅凭没说话推断需要情绪支持。 |
| C06 | 使用者刚说：“今天被批评以后很难受，想找人聊两句，不用替我解决问题。” | **需要情绪支持** | 有明确的情绪表达和陪伴请求；标签不授权其他行动。 |
| M01 | 现在上午十点。一位同事单独来信：“十点半的面谈临时改到另一栋楼，请确认是否看到。”使用者要参加这场面谈，通知真实且尚未读。 | **现在提醒** | 临近安排发生变化，延迟告知会妨碍使用者到场。 |
| M02 | 现在上午十点。一位同事单独来信：“下周三的面谈临时改到另一栋楼，周二前确认即可。”使用者要参加这场面谈，通知真实且尚未读。 | **攒着稍后看** | 有明确相关性，但当前没有紧迫到必须打断的期限。 |
| M03 | 同事单独转来项目记录。当前正文写“已处理完，仅供下周复盘，无需你操作”；引用的旧邮件写“紧急！今天十五点前处理”，该期限已过去且问题已解决。 | **保留但不立即提醒** | 引用中的紧急词不代表当前仍有紧急任务；保留复盘信息。 |
| M04 | 同事单独转来项目记录。当前正文写“尚未处理完，需要你今天十五点前确认方案”；现在十四点四十五分，使用者负责确认，尚未读。 | **现在提醒确认** | 当前正文明确有未解决的责任和临近期限。 |
| M05 | 一位普通联系人单独推荐一个下月活动。使用者明确表示不关注该主题，也未报名；邮件没有需要本人处理的事项。联系人未被屏蔽，也未列为重要联系人。 | **不主动提及** | 这是与使用者无关的信息；此标签不产生永久屏蔽规则。 |
| M06 | 一位普通联系人单独推荐一个下月活动。使用者此前说正在了解该主题；邮件包含有用议程，但未报名、近期无截止日期，也无需现在回复。联系人未被屏蔽，也未列为重要联系人。 | **保留稍后看** | 信息相关，但适合集中浏览，不必立即打断。 |
| T01 | 任务是修复路径兼容问题。上一轮模型写“已经修好了”，但没有任何文件修改回执、文件差异或测试结果。 | **先核对修改与测试** | 模型自己的完成声明不等于已验证的完成证据。 |
| T02 | 任务是修复路径兼容问题。已经独立检查文件差异，确认修复覆盖用户要求；相关回归测试和全量测试通过，无剩余待办，报告中有对应结果。 | **报告已验证的完成** | 已有可核实的完成证据，无需重复改动。 |
| T03 | 用户要求实现免邮判断。唯一依据是“超过 100 元免邮，100 元整不免邮”；金额计算方式已确定，无其他冲突要求。 | **按严格大于实现** | 明确的边界是严格大于，不能把它改成大于等于。 |
| T04 | 用户要求实现免邮判断。唯一依据是“100 元附近就免邮吧”；没有说明 100 元整是否免邮，也没有可查的业务规则。 | **先澄清边界** | 缺少边界定义时先澄清，不替用户猜业务规则。 |

## 审核后的后训练顺序

1. **先确定标签，再扩展数据。** 用你认可的判断标准扩写中文场景，加入否定、引用、时间变化、证据缺失和相近选项。合成标签只作候选，不能把模型自评当成人工事实。
2. **先留出测试组。** 按事件/情景组拆分训练、验证、校准和测试数据；同一对照组的改写与选项置换不能跨集合。首批 16 条只用于确定标注规则，不足以证明泛化能力。
3. **底座已选 Laya 多语言版。** 用户于 2026-10-15 选定 `convaiinnovations/laya-multilingual`；当前安装基础 checkpoint，待审核标签扩展后再做监督适配。先量中文判断、选项顺序敏感性、延迟和内存；Verdict 只保留为可选对比基线。
4. **监督训练与校准分开。** 先做小规模监督适配；采用 Laya 官方训练接口，先验证小批次 MPS 训练与导出加载。用独立校准集检验概率和弃权阈值，最后在未用于调参的测试集上与基线比较。中文否定和缺证据时的错误放行要单独统计。
5. **逐步接入真实反馈。** 将真实事件与当时可见证据关联后再审核标签；`ignored` 不能直接当作“不该提醒”，`read` 也不能直接证明“提醒时机正确”。保留反馈来源与时间，不使用后来才知道的结果作为当时输入。

拟记录：分类正确率、误打扰/漏提醒、选项置换后的判断一致性、置信度校准误差、弃权后的剩余错误、首轮/热启动延迟和峰值内存。验收标准在扩大训练前固定；没有达标就不部署训练产物，并保持保守降级和人工审批。

## 与这台 Mac 的模型升级衔接

本机为 M2 Max、30 核 GPU、64 GiB 统一内存。当前聊天和任务生成均已切换 DeepSeek，本地仅保留 Laya 与 EmbeddingGemma 2 辅助服务，见 [轻量运行架构](轻量运行架构.md)。

决策模型已选 **Laya 多语言版（约 322M 参数）**，基础权重与词表合计约 678 MB。`laya==0.4.7` 复用现有 PyTorch / Transformers；标准库不提供张量推理及决策头加载，因此需要该 Python 运行依赖。用户的 Laya 选型授权覆盖本次接入，不新增 Rust 依赖。中文效果、概率校准与后训练收益仍须用审核数据验证。

Laya 的训练接口已经包含在现有依赖中，本轮数据准备无需再添加训练框架。已下载的本地生成权重和 MLX 环境仅供实验，不用于决策微调。
