## 已实现的行为

聊天、任务和后台陪伴共享可编辑人格、画像与正式记忆。普通闲聊仍可直接回应情绪；只有需要时取用现有工具。用户原话经长度/凭证提示检查后形成有界观察，DeepSeek在单个后台工作线程中无工具整理候选，保存逐字证据、来源和时间。接受后才进入正式记忆；短期心情用有期限的事件，不覆盖长期偏好。原profile审核机制保留。

新增`companion_read`、`companion_update`，与已有58项工具共用注册与工具循环。查看返回记忆候选、正式记忆、跟进和近期通知，每类列表最多50项并注明截断。接受、拒绝、明确记住、纠正、忘记、建立/改期/取消跟进和标记已回应走逐次人工确认；预批准不跳过本次确认，拒绝规则优先。重复保存同一事实不增加重复记忆，伪造来源/证据拒绝。

可以说：“记住我喜欢饭后散步，因为这样能放松”；或者“明天下午面试结束后问问我的感受”。后者需要明确具体时间及必要的日历/待办关联，由Bot提议并经用户确认。后台每60秒检查到期的确认跟进：静默、退避、来源及有效期通过后，只读取关联日历/待办的最新记录，Laya留参考记录，DeepSeek无工具表达；投递前再次核对。日历结束不当成实际出席，改期、完成、消失或查询不完整都停止旧跟进。

通知标题标明“云熙 · 陪伴｜后续关心”。生成、系统投递、确认送达与回应分别记录；返回聊天可承接真实投递话题。固定标签和已投递状态防止一般重启重复；通知中心确认不等于用户看到了横幅或已读。后台模型计算不阻塞主循环，原生只读操作和Laya请求仍有自身延迟。

默认23:00–08:00静默，距最近真实输入或陪伴投递至少60分钟；未观察到回应时按2/4/8小时退避。无共享每日3次通知上限；整理/表达尝试共用独立48次/滚动24小时预算，预算耗尽记degraded。邮件原有通知机制和任务工具审批保持独立。

## 记忆撤回与数据升级

v1台账可读，新事件需`memory --upgrade`显式升级v2。迁移先校验、备份、同步写盘，保留全部旧事件字节。运行前须停止全部台账写入者；命令自身持有daemon锁。旧程序不能读取新v2台账；回退须归档升级后的数据并恢复匹配的旧程序和旧数据，不能删除新事件伪称无损回退。

忘记/纠正清除派生向量索引；下一轮清空可能残留改写旧事实的可见历史/摘要，重建上下文。有效期到达也使旧召回历史退出。此保守处理可能让早于撤回的其他候选/跟进也需重新确认，会牺牲部分连续性以避免旧事实复活。台账和旧会话档案仍保留，不是物理擦除。

```sh
# 交互入口和后台须使用同一数据目录
export YUNXI_BOT_HOME="$PWD/data"
target/release/yunxi-bot memory --pending
target/release/yunxi-bot memory --accept <候选ID>
target/release/yunxi-bot memory --reject <候选ID>
target/release/yunxi-bot memory --followups
```
