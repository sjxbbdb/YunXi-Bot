# 本地陪伴 T5：知识流水线

状态：2026-10-24，已实现并验证。

## 目标

把“值得长期保存的内容”分成两类，避免所有对话都进记忆或知识库：

```text
ConversationObserved
  ↓ Laya 记忆门控（store / skip）
  ↓ store
Laya 知识门控（memory / knowledge）
  ├─ memory → T3 本地记忆流水线
  └─ knowledge → 知识入库 + 知识向量
```

## 实现

- `retrieval::import_text(home, source, text)`：对话知识直接写 `knowledge/documents`，来源如 `conversation#42`。
  - 同内容跨来源去重，返回已有 id；
  - 同一来源不同内容拒绝覆盖，避免自动流水线改写旧资料；
  - 内容上限 2MiB，空内容拒绝。
- `gate_knowledge`：Laya 判断 memory/knowledge；显式线索（“知识库/资料/文档/以后查/教程/定义/步骤/端口/协议”等）在 Laya 误判 memory 时兜底为 knowledge；失败默认 memory。
- `clean_knowledge_text`：剥掉“记住这个知识：/记到知识库：”等指令前缀，只保存知识本体。
- chat-server 空闲流水线与 daemon 的 `--agent` 兜底都接入了知识门控；知识路径与记忆路径共用 `memory.lock`。
- 知识入库后清除并重建 `vectors/knowledge.json`；来源保留在文档中，后续检索可引用。
- 没有可用本地 embedding 时知识仍落库，向量化失败只记录，不阻塞；不调用云端。

## 已知限制

- 自动知识判定仍可能把一般事实放进知识库；显式“知识库/资料”意图最可靠。没有人工复核队列。
- 知识文档版本固定 v1；同来源不同内容拒绝覆盖，需要用户先 remove 再导入。
- 旧版测试文档正文包含“记住这个知识：”前缀；新写入会清洗。
- 知识召回尚未接入陪伴聊天，T6 做自动召回与来源展示。
