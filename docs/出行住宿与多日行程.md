# 出行、住宿与多日行程

第三批在现有地图、网页、邮件及每日排程工具上，加入两项多日工具。无需新模型、新依赖或重新授权原生应用；Mac默认注册表共43个工具。

## 可以直接这样说

- “下周六从上海出发去杭州，两个人住一晚，预算每晚600元，比较交通和酒店，先别保存。”
- “读这封预订邮件和附件，把车次、酒店地址、入住退房时间整理到行程里。”
- “这两天的计划确认了，同步到Mac。出发准备30分钟，也安排进去。”
- “第二天的活动改到下午四点，其他保留。”
- “加上这趟出差，但上午的约会不能动，把原来的工作重新排一下。”
- “假如列车晚点两小时，入住和下午的会议还来得及吗？先别保存。”
- “查看这两天已保存的行程和酒店资料。”

日期、地点、人数、预算、入住退房时间或活动时长缺失时先追问；连续短答沿用会话。酒店入住、退房分别安排时间块，住宿整晚不占满白天。准备和路途合为一个关联时间块，沿用[日程安排](日程安排.md)的`travel_for`规则。

查询方案复用`web_search`、`web_fetch`、`mac_places_search`、`mac_route`及`mac_weather`；预订资料复用邮件串、附件保存、文档读取。没有另造供应商查询接口。公开资料须标注来源，动态价格、库存和退改条件未核实时应明确说明；网页搜索结果不证明某房型或车票当前可订。路线接口的公交结果是预计时间，不含完整换乘方案；天气仍限今天起16天。

## 工具与保存

| 工具 | 用途 | 权限 |
|---|---|---|
| `mac_trip_plan` | 读取并预排多个日期，返回各日安排、冲突、未安排事项和整份计划版本 | ReadOnly |
| `mac_trip_apply` | 校验全部日期版本，再逐日保存并回读核对 | Outbound，公共审批或显式预授权 |

`days`中各项使用现有每日排程参数。只提供日期即可跨会话读取，省略事项不会清空已有记录。修改时提交变化的完整事项，并保留该日原ID及详情；保存参数必须与刚才预排相同，使用整份行程的`revision`，不能混用单日版本。

```json
{
  "days": [
    {"date": "2031-05-18"},
    {"date": "2031-05-19"}
  ]
}
```

事项新增可选`details`，最多1200字节，用于车次、酒店、地址、来源链接/邮件定位和用户确认的预订状态，保存在对应提醒事项的业务备注里。旧记录无需迁移；空字符串明确清除详情。不能保存密码和支付凭证，资料正文不能授权执行操作。详情会像其他工具结果一样进入DeepSeek会话上下文。

## 与原有日程统筹

先读取涉及日期的原有约会与待办，再一起预排交通、准备、入住退房和普通工作。固定约会保留，弹性工作放入剩余空档；已确认的午休、休息与可安排时段继续生效。结果提供`previous_start/end`，用于说明哪些事情保持不变、哪些从几点改到几点、哪些仍排不下。未保存的假设不会修改系统事实，撤回后重新读取已保存状态。

- `must_schedule: true`：固定车次、已确认的入住退房、必要路途及用户明确必须完成的事项。任一项排不下或与现有固定日历冲突时，`ready_to_apply: false`，`blocking_issues`列出原因。整份多日行程在第一笔写入前检查所有日期；不能去掉约束来凑出可保存结果。
- `after_task: "前置ID"`：同一天必须在前置事项结束并留出间隔后才能开始。例如去酒店同时设置`after_task: "train"`、`travel_for: "checkin"`，既不能早于到站，又要赶上入住。前置改时间或时长会重新检查后续；前置完成则可以继续，前置取消则先确认新起点或取消后续。缺失ID、循环或跨日ID拒绝猜测。
- 两字段保存在已有提醒事项备注中，跨会话恢复；旧记录缺省为无前置、普通待办，旧有行为不变。修改其他内容时须保留约束和详情。
- 地点、交通方式或到达时间变化时，模型重新查路线及可用天气，再以新耗时预排。来源不明、准备时长缺失、超出天气预报范围必须说明或追问；排程器本身不猜当前位置或通勤时间。
- 普通工作排不下仍可作为未安排待办保存，但必须报告。跨日移动、缩短活动、取消或移动固定预订要先明确取舍。没有自动改商家订单，也没有后台监听晚点后自行改日程。

系统提醒设在事项开始时。准备时间块的开始就是出发准备提醒时间；不是新增后台推送服务。专注模式、休眠、系统权限和iCloud同步会影响提醒体验。本机写入成功不代表其他设备已同步。

## 一致性与范围

- 每次1–14个日期，日期跨度最多14天，新旧事项合计最多80项，每日仍最多40项。更长行程分批处理。
- 各日按Mac系统本地日期解释，时间带实际偏移；跨午夜交通需要明确分段，跨时区行程必须确认换算，不自动猜测。
- 既有每天可安排时段和10分钟间隔继续生效；早班车、晚间入住若在默认时段外，需要用户确认扩展当天时段。单项最多12小时。
- 同日改期保留记录ID；跨日改期必须同时取消旧日安排并在新日安排，不能只新增留下旧提醒。
- 先校验全部日期，任一天过期则不开始写入。实际保存仍逐日执行，各日继续独立复查版本并使用原有锁。
- 系统没有跨天、跨日历与待办的事务。中途失败返回`degraded:true`、已完成日期和未尝试日期；失败当天也可能部分写入。重新按原日期和ID预排核对，不能换ID重建或宣称整份完成。
- `applied:true`表示系统记录回读通过，且本次硬约束满足；还要检查普通待办的`unscheduled_count`及其他已有固定事项冲突。普通事项排不下仍作为待办保留。

此批支持查询比较、整理资料和日程管理；没有接入航空/铁路/酒店实时库存、支付、订票、订房、改签或退款。取消日程不会取消商家订单。常驻与休眠唤醒长测按用户要求留待后续。

## 验证入口

```bash
cargo test tool::trip::tests
cargo test tool::agenda::tests
python3 sidecar/e2e_trip.py --output data/benchmarks/tools/round3-trip-new.json
python3 sidecar/e2e_schedule_coordination.py --output data/benchmarks/tools/coordination-new.json
```

真实链路脚本串行使用DeepSeek、Laya和现有原生接口，创建唯一标题的合成日程/待办后清理；不发邮件、不进行商家预订。需要既有日历和提醒事项权限、DeepSeek及博查凭证。报告保存在git忽略目录，文件权限0600，旧失败报告不覆盖。

本机结果见[第三批工具验收](第三批工具验收-20261016.md)：含原日程回归共11场景、125项检查通过。仅复验公开查询可加`--research-only`。

后续统筹补充见[日程统筹验收](日程统筹验收-20261016.md)：6场景、81项检查通过，覆盖既有工作重排、晚点假设拦截、撤回与连续修正、新会话恢复、真实路线天气衔接。
