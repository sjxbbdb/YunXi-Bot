## 专用浏览器

`browser_prepare(allow_launch=true)`默认使用`isolated_named/yunxi-bot`。它是Cua启动的独立Chromium实例与独立配置，复用系统已安装、经上游验证的Chrome/Edge内核；不是重新开发浏览器内核，也不是读取日常浏览器的Cookie。旧`yunxi-recorded-travel`配置保留，显式给该名称仍可使用；日常Edge接入继续需要原有授权。

命名配置由上游放在macOS的`~/Library/Application Support/CuaDriver/BrowserProfiles/yunxi-bot`。初始化会限制目录权限；配置不在Git工作区。截图、原始界面结果和动作输入继续只在当前进程保留。

必须区分持久配置与常开进程：Cua会在会话结束时回收所拥有的浏览器。**实测正常退出后localStorage跨会话保留；立即强制结束会话可能丢失刚写、尚未落盘的状态。** 源码ManagedBrowser::drop使用SIGKILL。未修改上游二进制来掩盖这个限制，也不自动关闭有未保存内容的用户窗口。站点登录过期、验证码仍需用户接管。未声称永久登录或24小时常开。

## 学习与回放

模型先`browser_workflow(list/inspect)`查找流程。没有合适候选时，在已观察的精确标签上`begin`，从导航开始正常做任务；适配器将实际成功的导航、唯一role/name点击、replace=true输入自动提炼为候选步骤。原生操作、切换标签、不支持动作或失败使学习失效；回合/人工接管后清除内存候选。完成后重新观察，`browser_workflow_save(success_text)`核验实际文字再保存。

候选是有版本的JSON步骤，不是任意可执行JS或Python。输入值、URL路径/查询、成功文字、旧ref、截图不保存；保存来源origin与语义定位。输入按`input_1`等步骤号参数化，核验文字通过本次`expected_result`提供。站点origin固定；另一域名需重新学习。输入凭证、验证码、付款信息不适合学习。

示例结构（实际步骤由真实调用提炼）：

```json
{
  "version": 1,
  "name": "search-example",
  "steps": [
    {"kind":"navigate","origin":"https://example.org","parameter":"input_1"},
    {"kind":"type","origin":"https://example.org","locator":{"role":"textbox","name":"目的地"},"parameter":"input_2"},
    {"kind":"click","origin":"https://example.org","locator":{"role":"button","name":"生成预览"}}
  ],
  "final_origin":"https://example.org"
}
```

`browser_workflow_run`由ToolRunner展开：读取候选 → 每步观察 → 唯一语义解析 → 原有preflight/门禁/人工审批 → 派发一次 → 下一步重新观察 → 最终条件等待与computer_verify。内部不调用模型规划，每个内部调用仍单独审计，并纳入结果调用清单。直接调用工具实现不能绕过runner执行流程。

上层调用不意味着批准内部全部动作；默认无人值守审批者仍拒绝，生产没有测试用的自动批准。订单提交继续经过travel_checkout约束。中途失败返回`degraded=true`和步骤号，停止后续动作，不自动修脚本或整段重跑，先重新观察并交给模型/用户。候选每次回放都核验，过去成功不是永久许可。

流程保存在应用数据目录`browser-workflows/`，目录0700、文件0600；新名称创建，不覆盖旧流程；不跟随文件符号链接，拒绝坏格式/超限/目录穿越。通过临时文件与不覆盖链接发布完整文件。它是可删除的本地复用资料，不改变台账格式或审批词汇。
