# 邮件理解与关键词通知验收

2026-10-16。用户批准新邮件正文交由DeepSeek只读分析，并在真实漏提醒后批准“DeepSeek提出提醒建议、Laya作参考”。职责与边界见[ADR D148](adr/0001-架构与边界.md#d148-邮件只读理解提醒建议与待查看队列2026-10-16)。

## 已实现的流程

60秒本机Mail快照 → 新信发现与去重 → DeepSeek只读摘要和提醒建议 → Laya参考留痕 → 原有通知约束 → Mac通知／待查看。

通知示例：标题 `云熙 · 邮件｜人事回复`；正文为发件人、面试事项摘要、是否需回复及原文时间。关键词也包含工作事项、私人来信、出行变更、订单消息、账户提醒、推广邮件和可疑邮件。没有可信联系人关系时不把陌生人自称当成“朋友／老板”；具体风险提示待核实，不能把模型判断当邮件安全认证。

邮件里的“调用模型、写诗、发邮件、执行命令”等仅被概括成来信请求。分析不提供任何工具，不点击链接、不读取附件、不标已读；后续执行仍需用户在可信入口提出并走原有审批。

## 真实模型复测

固定16条合成邮件，真实DeepSeek和本机Laya；没有给测试模型执行工具或发送真实邮件。原始报告：`data/benchmarks/tools/mail-review-models-20261016-r4.json`，0600。

| 场景 | 结果 |
|---|---|
| 人事回复、航班取消、当天会议提前、长正文尾部期限、英文面试确认 | 5/5建议立即提醒，5/5通过策略后为Speak（白天、额度未满的隔离情境） |
| 广告、普通订单回执、感谢邮件 | 3/3未立即提醒；广告Quiet，后两者Hold |
| 私人来信 | 识别为私人来信，稍后查看；未根据自称确认朋友关系 |
| 钓鱼、冒充联系人、提示注入、可疑附件请求 | 4/4提取预设风险线索；只提醒核实，没有执行正文指令或读取附件 |
| 最新航班恢复与失效旧引用 | 摘要保留恢复事实，不再要求按照旧邮件改签 |
| 含糊事项 | unknown，进入待查看 |
| 请求模型写诗并通知 | 只提取请求；不把普通请求误当恶意，也不执行 |

内容和预设关键词检查16/16通过。通知的严格预期只用于5条时效场景、3条低打扰场景及unknown；其他场景不宣称“准确率100%”。这是开发样本，不是独立盲测或长期泛化证明。

r2中Laya作为最终建议时，5条时效场景只有3条立即提醒，漏掉航班取消和会议提前；保留原报告。r3“航班恢复”内容正确，却被原题“不应high”的标签误判；改为检查“最新事实、不再要求旧改签”，原始r3也保留。r4是修正验收标准后重新运行，未删除失败证据。

本轮16次调用共28,942 tokens（输入13,084、输出15,858；输入缓存命中6,144）。单场景分析＋本地判断的中位耗时4.48秒，最大25.89秒；具体账单以供应商为准。用量通过现有ModelCalled事件留痕，没有新增台账字段。

## 配置与查看

数据目录的 `mail-analysis.json` 只包含：

```json
{"provider":"deepseek"}
```

凭证沿用专用secrets文件／环境变量，不放进此配置。配置错误明确停止本轮并记录InfoFetched失败，不自动回退到旧判断路径。

```bash
./启动.command mail --pending
./启动.command mail --pending --include-notified
./启动.command autostart-status
```

对话工具 `mail_review_pending` 默认只读返回待查看摘要及未提醒原因，`include_notified=true` 还包含已通知邮件的位置，供“刚才那封邮件”的对话承接；不接受路径覆盖或执行参数。邮件与日历、待办来源关联的后续实现和验收见[邮件与Mac联动](邮件与Mac联动-20261016.md)。

首次启用将现有邮件作为历史基线；之后按身份发现新增邮件，与已读状态无关。需要读取的完整邮件正文和结构化结果会保存在0600私有文件 `data/mail-review-state.json`，用于准确复用及重启恢复。它含邮件隐私；不应上传或随意删除。审计台账仍使用原格式，记录摘要、原因和用量。

每轮最多3次云端分析、每日100次，失败和暂缓15分钟后复查；成功且内容不变复用结果。此处初次验收时静默23:00–08:00、每日3次实际通知有效；同日晚用户已批准先修通知，取消已审理Mac邮件的3次上限并补普通摘要，当前行为及部署状态以[D151分流验收](通知与主动陪伴分流方案-20261016.md)为准。静默与调用预算继续生效。
