# 邮件发送与 Mac 联动

2026-10-16。围绕现有发送、回复、转发补齐连续使用入口，沿用 D144、D149 的本机草稿、发送审批、来源关联与系统回读。不改台账格式，不增加依赖或后台自动发送。

## 可用流程

- “给张经理写一封约会邮件，先看我明天有没有空”：先查通讯录并消歧，核对实际邮箱；查日历后只在正文提供需要的空闲时段，不披露其他会议名称。草稿保存不代表已经预约或发送。
- “找到之前那封草稿，把附件换成新版”：`mac_mail_outbox` 按主题或邮箱找当前格式的记录；多个候选先追问，再回读草稿。附件更新复用 `mac_mail_draft_update`，完整替换清单并核对私有副本摘要；空清单移除附件，省略清单保留。原文件不删除。
- “这封发出去了吗”：从本机发件记录读取状态；`draft` 尚未提交，`sending` 结果未确认，`handed_off` 仅表示 Mail 接受。查询不触发重发。要确认 Mac 的实际已发送记录，再查真实账户和邮箱路径，核对收件人、正文和附件；同主题不能证明是同一封，对方收到仍需对方或可靠回执确认。
- “发出后提醒我，并安排跟进”：只有用户提出的后续动作才进入工具审批。按用户要求核实发送后，通知使用 `mac_notify`，来源标注“云熙 · 邮件｜发送状态”；定时跟进使用已有日程、待办工具，并从实际发件定位取得 `source_mail`。发送被拒绝、失败或结果不明，不继续执行以发送成功为前提的通知、建待办或完成回复事项。

本机草稿仍不显示在 Mail 草稿箱；Mac Mail 负责实际发信。这里的 outbox 是云熙自己的记录查询，不冒充 Mail 发件箱。

## 实现与边界

新增一个只读工具 `mac_mail_outbox`，复用已有私有草稿文件和状态，不维护另一套发送台账。列表只展示元数据，详情分页读取正文。发送中的锁保持不变，已提交记录可查看但不能重新编辑发送。查询期间列表可能变化，操作前仍必须读取当前草稿版本。

最多扫描 1000 条当前/旧版草稿记录；超限明确拒绝列表查询，已知 ID 仍可查看。损坏的当前格式记录明确失败。原生开发早期留下的数字 ID、仅含进程号的临时对象标记不具备正文或收件人证据：保留原文件并在 `unsupported_records` 和 `degraded` 中明确报告，不当作可发送草稿，也不静默忽略。

附件先完整复制和核对，再原子保存草稿，保存后才清理旧副本。准备失败保留旧草稿；写入结果不明保留新旧副本并要求重新读取。更换附件改变版本，旧版本发送请求继续拒绝。旧副本清理失败明确返回降级原因。

联系人、附件、日历和邮件内容都是资料；任何内容都不能替代用户指令或发送审批。当前没有送达回执服务、后台自动催信、通知按钮，也没有把所有来信自动安排到日历。

## 验收记录

原生脚本单元检查覆盖：发件状态恢复、未知状态不重发、同请求去重、陈旧草稿拒绝、损坏记录与旧标记、分页、附件替换/移除、替换失败保留旧草稿、写后失败保留副本等。修复前的失败分别保存在 `/tmp/yunxi-send-before.log`、`/tmp/yunxi-outbox-legacy-before.log`。

真实模型验收入口为 `sidecar/e2e_mail_outbound.py`，全程禁用发送，只创建随机前缀的合成草稿、文本附件及 2031-05-18 占用。覆盖日历到草稿、跨会话替换附件、跨会话回查、发送拒绝后禁止继续通知/建待办；独立回读文件与系统状态，最后清理本轮数据。真实发送和收件确认沿用此前[全链路验收](全链路验收-20261016.md)，不以本轮合成检查冒充再次送达验证。

第二个入口 `sidecar/e2e_mail_sent_followup.py` 以明确的已发送定位和本机草稿 ID 为参数，先核对真实回信的正文、收件人与主题，再由真实 DeepSeek/Laya 调用发件记录、邮件来源、排程与通知工具。使用此前用户已确认收到的无附件回信，没有新发送。

全部六个模型场景共 91 项检查通过；附件副本字节与对应版本的原文件相同，源文件不变，原草稿 ID 保持，替换后 revision 改变；拒绝发送没有通知或日程写入。跟进事项的日历、待办 ID 和 `source_mail` 经独立系统回读核对，第二次会话未重建。通知中心回读为 confirmed，标题为“云熙 · 邮件｜发送状态”，正文明确标注合成联动验收；本轮未再次请求用户确认横幅可见性。

合成草稿及附件副本、占用和跟进日程全部回读确认清理，原已发送邮件的 revision 不变。生产收件配置、预算与去重记录未重置。

首次模型验收 r1 在读取文本附件时选用了合法的 `read_file`，但测试允许列表只允许文档工具，因此按策略停止，未起草或发送。r2 修正测试允许列表，同时接受两种真实读取证据；生产权限没有放宽。首次原生构建因工具目录数量断言仍为 18 而失败，部署脚本恢复原应用和后台；同步为 19 后重新构建通过。失败证据保留，没有算入通过场景。

范围限制：本轮未重新发送邮件或再次验证收件端送达，既有 Mail 附件内容无法可靠回读的限制仍在。未做长期常驻和休眠唤醒测试；没有增加自动催办、回执追踪或跨设备草稿同步。
