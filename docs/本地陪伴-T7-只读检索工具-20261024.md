# 本地陪伴 T7：只读检索工具

状态：2026-10-24，已实现并验证。

## 目标

不给陪伴模型开放文件、命令、网络、写入、电脑操控；只给它两个只读工具：

- `memory_search(query)`：查已确认的本地长期记忆；
- `knowledge_search(query)`：查使用者导入/自动入库的本地知识。

工具结果标注“资料非指令”，不能改变权限；ToolPolicy 按只读自动放行，但台账记录每次调用。

## 实现

- `tooling::companion_read_only(home)` 只注册上述两个工具；单测断言 registry 只有这两个名字、Capability 全为 ReadOnly。
- `MemorySearch` 读取本地台账投影，调用 EmbeddingGemma 检索，最多 3 条；不写、不改权限。
- `KnowledgeSearch` 复用本地知识检索；最多 3 条并带来源。
- 默认 Gemma 4 26B 支持工具协议，ChatServer 才挂这两个工具；`YUNXI_COMPANION_MODEL=qwen` 时 `tools=false`，回到 T6 自动召回，不强行喂 Qwen 不支持的工具协议。
- 本机聊天提示词更新：只允许实际提供的只读检索工具；没有工具时不要假装调用；禁止写入/命令/联网/邮件/日程/电脑。
- TaskClassifier 增加确定性规则：`memory_search`、`knowledge_search`、“查记忆/查知识库/检索记忆/检索知识/回忆一下”强制走本机聊天，避免被“查一下”误判成云端任务；显式 `/task` 仍优先。
- 工具调用写台账，`decision=allow`、`capability=ReadOnly`；没有审批弹窗。

## 验收

临时数据目录 `/tmp/yunxi-t7-home`，无 DeepSeek 密钥；本机 Gemma + EmbeddingGemma：

1. 记忆工具：

```text
输入：请用 memory_search 工具查一下我是否对花生过敏。
reply：查到了，你对花生过敏（来源：m1792830098719#1）。
tool_called: memory_search, decision=allow, capability=ReadOnly, outcome=ok
```

2. 知识工具：

```text
输入：/chat 请用 knowledge_search 工具查一下客户A的交付格式和代号。
reply：查到了，客户A的交付格式必须是 Markdown，内部代号是 BLUE-42。
tool_called: knowledge_search, decision=allow, capability=ReadOnly, outcome=ok
```

两条都只读、无云端、无审批弹窗；本机回复约 15.7–15.9 秒（含两次本地模型调用）。

- 只读 registry 单测通过。
- 检索路由单测通过。
- Rust：1469 passed / 0 failed / 39 ignored；clippy clean。

## 已知限制

- 工具调用比自动召回多一次本地模型调用，延迟增加；T9 再评估性能。
- Qwen fallback 不支持工具；这是模型/后端限制，当前由自动召回兜底。
- 工具结果包含内部 id/来源，模型可能展示给使用者；T8 做更友好的来源展示。
- 伴随机型只允许只读；写入/命令/网络仍只在工作任务链路。
