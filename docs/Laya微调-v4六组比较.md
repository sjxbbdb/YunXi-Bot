## 数据与选择规则

用户明确回复“认可这批新增标签，开始六组比较”。360个新增中文合成场景、540个判断，覆盖输入分类、记忆需求、工具建议、任务证据、陪伴介入和邮件分流。每类36个训练场景，另有验证、校准、终测各8个场景。

- 训练：216场景 / 324判断；验证、校准、终测各48场景 / 72判断。
- 原32场景、旧40题不参与本轮训练，用于开发回归；v3待审核12条未混入。
- 审核、分组、标签和导出文件均有哈希校验。已批准源文件的 canonical SHA256：`1e295acf77abba11715b9fcfc31d8f6bfbf24e41df886fe0790b176c79441b12`。
- 同一 multilingual 底座、同一数据和生产问句、相同学习率与预算，仅改变损失和种子。各组8轮、micro_batch=1、grad_accum=8，共328次优化器更新；encoder_lr=1e-5、head_lr=5e-5，choice 选项置换，FP32、MPS、梯度检查点。
- 每组按验证准确率、再按验证交叉熵选择 epoch。先比较三种子均值选方法，再在该方法中按验证准确率、交叉熵选择候选。完全相同时方法优先RLCD，种子按升序。
- 六组比较阶段没有拟合校准或评估终测。选择锁定后只对选中候选拟合校准，并比较该候选与底座；没有依据终测另挑其他候选。

所有540个判断均无输入截断、无选项截断；最长序列217 tokens，模型上限1024。分词长度审计不涉及模型预测。

数据：[审核表](Laya微调-v4扩展数据审核.md)、[批准标签](../models/training/project-review-v4.json)、[冻结方案](../models/training/project-experiment-v4.json)、长度审计（本机私有报告：`data/training/laya-project-v4-comparison/input-length-audit.json`，不随仓库发布）。

### 仍然存在的具体错误

正常选项顺序下的4处终测错误：

1. `V4-MEMORY-060`：同时要求长期阅读口味和上次阅读感受，期望 `mixed`，候选只选 `profile`。
2. `V4-TOOL-056`：`web_search` 会把查询发往外部，期望 `ask`，候选选 `auto`。
3. `V4-TOOL-060`：Python 命令调用 `open(...,'w').write(...)`，期望 `ask`，候选选 `auto`。
4. `V4-MAIL-059`：要求立即回复参观确认，正确识别需要现在提醒，却把 `needs_action` 判成 false。

反序还会让一题任务判断、一次异常介入判断从正确变错。旧40题剩余两错是“开心，顺便搜索附近书店”和“调用 now 告诉我时间”，均把任务判成闲聊。

旧32场景虽然总分提高，逐题比较仍有4个原本正确的判断退步：`R05`把“状态好，顺手查图书馆开放时间”判成闲聊；`T03`面对“严格超过200免邮”的明确证据仍选再次询问；`C01`无新事件、无异常却从quiet变为speak；`C04`把后台多次检查失败的异常标志判成false。旧40题没有新增退步，两处剩余错误基础模型也答错。不能只依据汇总准确率宣称没有能力回退。

工具题是结构化请求的分类测试，未执行其中的写入命令或网络搜索。不能据21项链路测试通过而声称这些错误已被安全覆盖：现有 `tool::ask_local` 对部分 `Execute` / `Network` 路径会将 `auto` 转为 `GateDecision::Allow`，`calibrated:false` 只是标记，不是拦截开关。`Outbound` / `Unknown` 的硬性审批与显式 deny 仍按原规则工作。本轮没有修改审批策略。

基础模型在相同工具题有4次 `ask → auto`，候选降为2次，但这仍是需要解决的问题。部署前应先审查相关硬性门禁，再用新的、经审核的失败边界与真实反馈验证；不能只靠继续训练承诺不会误放行。

### 实际 Bot 链路

独立端口17970加载候选，使用临时数据目录和真实 DeepSeek：**21项检查全部通过**。包括任务与混合输入读取临时文件里的真实暗号、闲聊与引用命令不带工具、同会话聊天→任务→聊天、决策服务故障时不生成、缺云端密钥时不回退本地生成。测试期间本地生成端口17872保持关闭。

这验证了接入契约与这些具体链路。未重新验收长期画像更新、完整知识库检索及所有任务分支；本轮memory题评估的是记忆需求分类，不能单凭它声称整个记忆系统的检索质量提高。

HTTP 单请求耗时中位数约24.72 ms（基础）和26.51 ms（候选），包含正常与反序请求，不含加载；仅是本机本批短输入测量。

## 校准结果与限制

选定候选后，仅使用独立 calibration 划分拟合温度：choice 48题，noul 24题；score没有样本，温度保持1。拟合温度分别约3.8451和1.7638。上游对两类都报告“小样本拟合”提醒。

| 新终测指标 | 候选原始温度 | 独立校准后 |
|---|---:|---:|
| 准确率 | 94.44% | 94.44% |
| 交叉熵 | 0.1953 | 0.1871 |
| ECE | 0.0474 | 0.0691 |
| 多类 Brier | 0.0821 | 0.0972 |

温度不改变类别。交叉熵略好，但 ECE、Brier 变差，不能称为“置信度已经可靠”。校准组本身仅55/72正确，和终测分数差距明显，说明划分间表现也不稳定。按原定流程保存拟合温度，并通过该配置跑HTTP测试；没有根据终测选择更有利的温度。

原始候选与温度拟合候选保存在不同目录；校准导出前后权重 SHA256 相同。服务继续报告 `calibrated:false`。证据：终测与校准明细（本机私有报告：`data/training/laya-project-v4-final/final-evaluation.json`，不随仓库发布）。
