# 电脑操控与国内出行：开源实现评估

核对日期：2026-10-17。依据公开仓库的 README、关键源码、接口说明与许可证；未安装这些项目、执行其脚本、登录旅行账户、查询真实库存或创建订单。本次为后续实现提供依据，没有修改当前工具注册、审批、模型路由或后台运行方式。

用户随后明确：票务、酒店和全量电脑操控都要。因此总体底座优先验证 Cua Driver，覆盖 Mac 原生应用与浏览器；agent-browser 改为浏览器专项候选。国内网页订票/订房借鉴 Travel Agent 的流程与人工接管，铁路查询参考 12306-mcp，酒店验证 RollingGo 官方 CLI 的结构化交易入口。保留云熙现有 DeepSeek、任务、审批与 Mac 日程工具。本结论是源码与架构适配判断，尚非本机兼容性、性能或交易可用性结论。

## 全量电脑操控：当前范围与首选底座

“全量”指覆盖通用操作类型，并与票务、酒店业务共同建设，不缩减为只有网页查询：

| 范围 | 应覆盖的操作 |
| --- | --- |
| 应用与窗口 | 找应用、启动与切换、列窗口、绑定目标窗口、调整位置和大小、处理关闭/未保存提示 |
| 界面理解 | 辅助功能树、窗口截图、必要时桌面截图、元素定位与坐标转换 |
| 通用输入 | 左/右/双击、输入、快捷键、滚动、拖放、精确目标上的值设置 |
| 系统交互 | 菜单、弹窗、文件选择器、文件拖入、剪贴板、人工接管与恢复 |
| 浏览器 | 标签页与地址、结构化页面观察、截图、控件输入、文件上传/下载、对话框 |
| 业务联动 | 国内票务和酒店查询/比较/订单准备/审批/查单，再联动日历、待办、通知 |

### Cua Driver

已核对的工具目录同时列出原生窗口、菜单、键鼠、剪贴板和浏览器工具；窗口观察能同时返回辅助功能信息及截图，元素令牌与观察绑定。它比仅操作 DOM 的执行器更贴合完整 Mac 助理目标；既有浏览器接口也可先验证，避免一开始同时安装两套操控底座。

资料：[实际工具目录](https://github.com/trycua/cua/blob/075add55cf938f4e351b74539efa18d4976696ae/.github/scripts/cua-driver-mcp-compat/expected-tools.json)、[目标与观察机制](https://github.com/trycua/cua/blob/075add55cf938f4e351b74539efa18d4976696ae/docs/content/docs/cua-driver/concepts/how-cua-driver-works.mdx)。

Driver 默认不需要模型权重，可继续让 DeepSeek 看图和选择动作；可选感知扩展另有模型与许可要求，首版不因“全量操控”默认引入它、虚拟机或另一套 Agent。Driver 的 MIT 许可也不能概括整个 Cua 仓库，Spaces 等组件仍有单独许可。

资料：[Driver 范围与许可](https://github.com/trycua/cua/blob/075add55cf938f4e351b74539efa18d4976696ae/libs/cua-driver/README.md)。

Mac 接入需验证 Accessibility 与 Screen Recording。独立运行应使用稳定的 CuaDriver.app 身份承载权限；直接把裸二进制路径当生产权限身份并不受支持。应用原生接口和 GUI 操控可同时保留，已有日历、邮件工具无需为了通用操控改成鼠标点击。

“后台优先”不等于所有动作都能后台完成：菜单、拖放、自绘界面和不同 WebView 的能力不同；驱动有明确的拒绝结果。旧教程与较新 Mac 专项说明对部分浏览器输入路线也有差异，落地须固定版本逐项实测，不能仅凭某段文档承诺不抢焦点。用户接管、前台操作和受保护界面都须明确处理，不能失败后静默换路线。

资料：[Mac 专项说明](https://github.com/trycua/cua/blob/075add55cf938f4e351b74539efa18d4976696ae/libs/cua-driver/rust/Skills/cua-driver/MACOS.md)、[动作支持矩阵](https://github.com/trycua/cua/blob/075add55cf938f4e351b74539efa18d4976696ae/libs/cua-driver/docs/action-support.md)。

### UI-TARS Desktop

实际桌面 Operator 包含截图、点击、拖动、输入、快捷键及请求用户接管；截图实现显式处理 Retina 的物理/逻辑尺寸与缩放。这适合借鉴坐标校准和视觉动作转换。其现成桌面 UI、模型动作格式与运行栈不必整套移入云熙；DeepSeek 的函数调用及动作兼容性仍应独立验证。

源码：[桌面 Operator](https://github.com/bytedance/UI-TARS-desktop/blob/3ac2cb8d946d78d5ff92ad17b318eaafa18c178c/apps/ui-tars/src/main/agent/operator.ts)、[底层动作转换](https://github.com/bytedance/UI-TARS-desktop/blob/3ac2cb8d946d78d5ff92ad17b318eaafa18c178c/multimodal/gui-agent/operator-nutjs/src/NutJSOperator.ts)、[Mac 权限处理](https://github.com/bytedance/UI-TARS-desktop/blob/3ac2cb8d946d78d5ff92ad17b318eaafa18c178c/apps/ui-tars/src/main/utils/systemPermissions.ts)。

通用工具数量多不代表全部上游功能都直接暴露给模型。驱动的安装、更新、任意脚本、录像等管理接口与日常界面操作分开；业务审批仍由云熙实施。全量操作类型也不代表绕过 macOS、应用验证或不可逆动作批准。

## 1. agent-browser：浏览器专项候选

值得借鉴的是结构化页面快照和带出处的元素引用。其快照实现还有 iframe 文档/会话更换后引用失效的测试，适合解决“旧页面按钮引用还在，却已经不是同一个页面”的问题。截图及动作应与同一浏览器会话、同一页面关联，执行后再次观察。

源码：[快照与引用](https://github.com/vercel-labs/agent-browser/blob/dac13bb87468fe9d74a040d862720f6cc17a9565/cli/src/native/snapshot.rs)、[截图](https://github.com/vercel-labs/agent-browser/blob/dac13bb87468fe9d74a040d862720f6cc17a9565/cli/src/native/screenshot.rs)。

两个不能直接照搬的点：通用动作策略按导航、点击等类别划分，不理解“这个点击正在提交火车票订单”；策略加载帮助函数会把读取/解析失败转为缺少策略，因此云熙必须自己检查配置并保留审批门禁。另一个扩展中的截图示例刻意把图片交给 UI、向模型只回文字/JSON，这不等同于视觉观察能力。

源码：[动作策略](https://github.com/vercel-labs/agent-browser/blob/dac13bb87468fe9d74a040d862720f6cc17a9565/cli/src/native/policy.rs)、[截图示例的模型输出](https://github.com/vercel-labs/agent-browser/blob/dac13bb87468fe9d74a040d862720f6cc17a9565/packages/%40agent-browser/eve/extension/tools/screenshot.ts)。

它适合作为受限子进程执行器，不向模型开放任意 shell/JavaScript。当前 Mac 有 Edge，尚无 agent-browser；后续可验证是否能复用 Edge 的 Chromium 引擎，而不先安装另一整套桌面 Agent。这里尚未进行安装或兼容测试。

## 2. Travel Agent：最贴近国内网页订票/订房的参考

作者展示了携程机票和酒店的浏览器任务，已有可见浏览器、用户选择、表单准备、付款交还用户的流程。其接管状态机能暂停 Agent 操作，并等待正在执行的页面写入结束；敏感输入阶段连页面读取也会受限。适合参考验证码、短信与人工核对时如何交接控制。

源码：[人工接管状态](https://github.com/Prism-Shadow/travel-agent/blob/dd0ac16e1dc3d01a908cfaa907afdbcafdebe589/packages/browser-cli/src/executor/handover-state.ts)、[页面操作包装](https://github.com/Prism-Shadow/travel-agent/blob/dd0ac16e1dc3d01a908cfaa907afdbcafdebe589/packages/browser-cli/src/executor/write-gate.ts)。

关键限制：支付/提交拦截是按控件文字匹配；无标签时不拦截。作者也明确它不是安全边界。云熙不能沿用这条未知即继续的分支；订单创建和取消仍须从已回读的业务信息生成预览，经原有逐次审批，目标或金额变化后重新核对。公开演示也不能替代本站实际端到端验收。

源码：[支付拦截实现](https://github.com/Prism-Shadow/travel-agent/blob/dd0ac16e1dc3d01a908cfaa907afdbcafdebe589/packages/browser-cli/src/executor/payment-gate.ts)、[对应测试](https://github.com/Prism-Shadow/travel-agent/blob/dd0ac16e1dc3d01a908cfaa907afdbcafdebe589/packages/browser-cli/test/write-gate.test.ts)。

可借鉴其“行程共享目的地、日期、人数和预算”的设计；云熙已有 Mac 多日行程工具，先把可靠的查询/订单信息接给它，不必引入完整 Electron 应用和第二套 Agent 状态。作者项目的任意 Playwright JS 执行入口也不直接作为云熙的通用授权入口。

资料：[行程上下文约定](https://github.com/Prism-Shadow/travel-agent/blob/dd0ac16e1dc3d01a908cfaa907afdbcafdebe589/packages/skills/skills/trip-workspace/SKILL.md)。

## 3. 12306-mcp：借鉴铁路数据与查询，不能当作购票接口

实际注册的是日期、城市/车站编码、余票、中转换乘与经停查询。可参考城市与具体车站的区分、席别/价格解析、同日换乘及上海时区处理。未见创建订单工具；它依赖网站初始化、Cookie 与网页查询路径，属于第三方适配，不是 12306 官方开放平台。

源码：[查询工具与数据解析](https://github.com/Joooook/12306-mcp/blob/ff6439da6f63d7d72181abea4568abd69878c600/src/index.ts)、[实现原理](https://github.com/Joooook/12306-mcp/blob/ff6439da6f63d7d72181abea4568abd69878c600/docs/principle.md)。

建议借鉴查询数据结构与测试条件。创建订单另走用户已登录的官方页面，不能把查到余票当作可出票保证；候补、无座、售罄、未知和查询失败分别表达。本轮没有验证其真实查询时效或网站访问稳定性。

## 4. RollingGo：官方酒店流程比纯视觉更便于核对

本次进一步读取官方 Skill 和参数文档，确认它们已列出订单详情、预取消和确认取消：先回读费用及确认凭证，再请求用户确认，最后提交取消。这补充了先前只看 README 时缺少的取消契约信息；仍未验证已发布 CLI 版本与账号权限。

资料：[官方参数表](https://github.com/RollingGo-AI/rollinggo-hotel-skill-cn/blob/98c500b26777e3ba1d1d5f5da74eddea6b15a5a7/skills/rollinggo-hotel-booking/references/cli-params.md)、[官方流程](https://github.com/RollingGo-AI/rollinggo-hotel-skill-cn/blob/98c500b26777e3ba1d1d5f5da74eddea6b15a5a7/skills/rollinggo-hotel-booking/SKILL.md)。

该仓库主要分发说明和安装入口，不能据此声称已审计实际 CLI 的网络/交易实现。借鉴“搜索→房型→验价→用户确认→生单→查单”和“两步取消”；房态可为空、待确认不等于有房，文档中的约定时长不冒充本次报价/支付的精确截止时间。取消成功也不代表退款已经到账。

酒店仍需按日期、人数、儿童年龄、房间数、餐食、退改与含税总额核对。官方结构化入口若能开通，优先用于该渠道的真实库存与订单；其他平台比较再用浏览器，保留来源差异。

## 5. browser-use-hotel：参考国内多平台查询，不搬云端展示栈

源码把携程、去哪儿、同程分成配置，查询支持串行和并行，单平台失败可独立报告；查询失败时可切换桌面/移动入口，遇到验证码停止尝试。适合借鉴查询编排。其实际 Agent 配置关闭视觉，截图回调用于上传展示，所以截图直播不能直接证明模型已看图。

源码：[平台查询 Agent](https://github.com/kevinten-ai/browser-use-hotel/blob/c3dbcf7d1980a7363cacc7a3847735a43e592e11/hotel-compare/browser-use-version/agent_factory.py)、[查询与回调](https://github.com/kevinten-ai/browser-use-hotel/blob/c3dbcf7d1980a7363cacc7a3847735a43e592e11/hotel-compare/browser-use-version/hotel_compare.py)、[失败分类与入口切换](https://github.com/kevinten-ai/browser-use-hotel/blob/c3dbcf7d1980a7363cacc7a3847735a43e592e11/hotel-compare/browser-use-version/retry_strategies.py)。

云熙优先串行操作一个受控浏览器，不复制其 Supabase 截图上传、前端和云端 Worker。其价格结果结构也不足以直接作为云熙最终订单报价：还需补日期、人数、币种、费用口径、退改规则及原页面证据。查询重试策略绝不能用于结果未知的提交订单动作。

## 6. DeepSeek 官方 Harness：参考适配与资源归属

官方把任务循环和浏览器/桌面执行器分开。Playwright MCP 适配器固定实际浏览器启动方式、清理可能改变模式的环境配置，并按会话维护资源；原生 Cua Driver 适配器处理启动失败清理、取消和资源回收。适合参考宿主与执行器的责任分配。

源码：[Playwright 适配](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/experimental/browser-use-playwright-mcp/src/index.ts)、[Cua Driver 适配](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/experimental/computer-use-cua-driver-native/src/index.ts)。

浏览器按 Session 归属不意味着本机桌面已被全局锁定；共享桌面还需宿主协调完整的观察、操作、核验过程。官方图片适配走 Messages 协议，与云熙当前 Chat Completions 请求不同，不能仅复制一个 SDK 调用。没有必要为此把整个 Harness 换进来。

资料：[桌面共享边界](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/docs/subsystems/computer-use.md)、[图片及请求适配](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/llm/llm-deepseek/src/adapter.ts)。

## 对云熙下一步实现的具体建议

1. 先验证通用 Mac 执行器，打通应用/窗口/菜单/键鼠/截图/剪贴板/人工接管，并验证它已有的浏览器工具；再判断是否补 agent-browser。票务与酒店是共同交付的业务功能，不替代通用电脑操控。一次只运行一个完整操控流程，防止并发抢桌面及页面；已有原生业务接口继续复用。
2. 补工具截图到模型的受控图片通道。刚完成的 D152 是用户手动附图，现有 ToolOutput/工具循环仍只携带文字；图片工具输出尚不会自动进入模型。图像保留不可信工具来源，不把网页文字当授权；原图不进普通审计。旧帧保留/淘汰、协议适配及图片来源规则需单独设计。
3. 业务层明确查询、报价确认、订单预览、创建、查单与取消。预览包含日期、区间/酒店、人员、席别/房型、总价、条款、来源和页面版本；审批不与通用点击长期绑定。失效引用、未知提交结果或目标变化停止推进。
4. 第一条铁路验收采用 12306 官方页面，酒店先验证结构化候选渠道及携程网页。只读比较不修改 Mac 日程；用户批准预订并回读真实订单后，交给已有多日行程预排，统筹路途、准备、入住退房与固定安排。
5. 登录验证、付款由用户处理；未知结果先查订单，不重新点击提交。日程同步失败只恢复同步，不重新预订。当前直接创建/修改日历工具缺少统一冲突校验的已知缺口，也应在正式订单回写前补上。

这些是后续实现建议，尚未注册新工具或安装运行依赖。若选定执行器需要新增运行时依赖或修改既有 ADR，按项目约定先提交具体范围确认；不据本研究默认启用交易能力。
