# 项目全貌与接线现状

核对日期：2026-10-15；2026-10-16 更新已变更的模型、邮件和连续对话接线。依据当前工作区源码、入口装配、ADR 演进与本机验收记录。
这是结构和主链路核对，不是逐行安全审计；未据此宣称 7×24 稳定。

当前生成统一使用 DeepSeek，本地仅保留 Laya 和 EmbeddingGemma 2 辅助服务；详见 [轻量运行架构](轻量运行架构.md)。

## 1. 实际结构

项目是一个具体的 Rust 助理内核，加 CLI 装配与独立 Python 模型服务。没有必要因换到 Mac 重写 Rust 核心。

| 部分 | 主要源码 | 实际职责 |
|---|---|---|
| 命令入口 | `crates/yunxi-bot-cli/src/main.rs` | 装配 chat、do/resume、daemon、agent/check 等不同运行路径 |
| 对话与模型调用 | `chat.rs`、`chat_handler.rs`、`think/` | 系统提示词、历史、压缩、路由、OpenAI 兼容 HTTP/SSE |
| 目标任务 | `task/model.rs`、`plan.rs`、`engine.rs`、`schedule.rs` | 目标拆解、依赖、步骤执行、决策点、人工续跑、守护接手 |
| 定时作业 | `job.rs`、`trigger.rs`、`runner.rs` | 命令式 Job 状态机、定时/cron/文件触发、审批与执行 |
| 治理 | `ledger.rs`、`policy.rs`、`tool_sink.rs`、`costlog.rs` | 追加事件、重建状态、审批约束、工具与模型调用留痕 |
| 陪伴与信息巡览 | `agent.rs`、`companion.rs`、`assistant.rs`、`triage.rs`、`feedback.rs` | 内部状态介入判断、邮件分拣、通知、反馈去重 |
| 记忆与人格 | `persona.rs`、`profile.rs`、`memory.rs`、`embedding.rs`、`recall_gate.rs`、`rules.rs` | 助理人格、用户画像、长期记忆、召回门控、项目规则 |
| 工具 | `tool/`、`mcp.rs` | 文件、命令、网络、问人；工具循环与外部 MCP 客户端 |
| 平台执行 | `exec.rs`、`instance.rs`、`notify_*`、`detach.rs`、`autostart_macos.rs` | 子进程、进程组、单实例、通知、后台启动、自启 |
| 服务与开发脚本 | `sidecar/`、`scripts/`、根目录启动器 | Laya、生成模型、邮件 sidecar；安装、下载校验、基准与集成测试 |

相对路径中未写前缀的核心源码位于 `crates/yunxi-bot-core/src/`；CLI 辅助文件位于 `crates/yunxi-bot-cli/src/`。

## 2. 五条入口不能视为同一条链路

1. **聊天**：CLI → ChatHandler → 输入分类/召回 → 路由 → 工具循环 → 会话落盘。
2. **目标任务**：do/resume → Task Engine → 规划 → 逐步执行/选择方案 → 事件台账。步骤结果被传给后续步骤；这不等于获得了完整聊天记忆。
3. **定时作业**：add/tick/daemon → Job 调度 → 策略门禁 → 子进程。它直接执行 argv，不经过生成模型。
4. **主动陪伴**：agent/daemon --agent → 从台账派生现状和记忆 → Laya → 安静时段/频率等约束 → DeepSeek 表达。
5. **邮件巡览**：check/daemon → Mac Mail（其他平台可用 IMAP）→ 已启用时 DeepSeek 只读审理 / Laya 参考 → 通知策略 → 原生通知 / 待查看 → 反馈台账。

daemon 顺序执行这些回合；长模型调用会占用本轮时间。它不是每项能力都有独立调度线程的系统。

## 3. 上下文实际接线

| 内容 | chat | do/resume | daemon 中的目标任务 | 主动陪伴 |
|---|---|---|---|---|
| 自定义 persona.md | 有 | 有 | 有 | 使用独立固定表达提示词 |
| profile.md 用户画像 | 有 | 每阶段刷新 | 每阶段刷新 | 未读取该文件 |
| 常驻事实/偏好 | 有，handler 创建时快照 | 每阶段刷新 | 每阶段刷新 | 从记忆投影另行取证据 |
| 随问题动态召回 | 有，词面与字符向量融合 | 门控后用 EmbeddingGemma 2 | 同左 | 按类别/权重选取，不是同一套问题召回 |
| 项目 AGENTS.md/CLAUDE.md | 有 | 每阶段刷新，读取失败停止 | 同左 | 未接 |
| 内置工具 | 按连续对话提供，含知识检索 | 有，含知识检索 | 有，需批准时拒绝 | 不走工具循环 |
| MCP 工具装配 | 有 | 未装配 | 未装配 | 未装配 |
| 跨进程聊天历史 | sessions 文件 | 从任务台账恢复步骤状态/结果，不恢复聊天会话 | 同左 | 依据台账派生情境 |

关键调用点：`ChatHandler::stable_prefix` 已向所有意图注入画像、常驻记忆和规则；`with_recalled_memory` 仍只负责聊天旧召回。
`TaskHandler::plan/execute_step/observe` 共用 `task_context` 刷新快照与语义检索，并拼接目标、步骤指令与前置结果。
MCP 的实际装配调用位于 chat/tools 等入口，不能由“项目有 mcp.rs”推断每个入口都能调用 MCP。

## 4. 记忆、向量和知识库不是同一个完成状态

- 长期记忆：存在，以 `ledger.jsonl` 中的事件投影重建；支持事实、偏好、关系、事件和工作区记忆。
- 画像：存在，`profile.md` 是用户档案；模型提炼结果先形成候选，人工接受后才改变档案。
- 向量召回：聊天保留256维字符 n-gram + IDF/RRF；目标任务新增 EmbeddingGemma 2 真正语义编码、工作区过滤及有界持久缓存。
- 独立知识库：新增显式文本导入、分块、独立向量缓存、检索/移除/重建命令与 `knowledge_search` 工具。同一数据目录的知识副本共享，不是项目权限隔离库。
- ADR 中引用其他 YunXi 项目的 SQLite/向量存储研究，不代表这些实现已经复制到本仓库。

目标任务的接线已补齐，使用方法和验收边界见 [任务上下文与知识库](任务上下文与知识库.md)。这不代表所有入口统一，也不代表7×24稳定性已验证。

## 5. Mac 适配与剩余重点

已经有原生 arm64 Rust 构建、DeepSeek 生成、MPS Laya、Unix 进程组回收、Mac 进程存活检查、通知中心和 launchd 自启。
Windows 的 Job Object/低完整性令牌仍作为 Windows 实现保留。Mac 当前报告 ProcessOnly；要求 OS 写隔离时拒绝执行，不把工具路径策略当成 OS 沙箱。

需要继续核对的事项：

- `memory::normalize_scope` 仍按 Windows 习惯把 `/` 改成 `\`。旧 Windows 工作区路径也不会自动匹配 Mac 路径；应先明确迁移与匹配规则，再改已持久化 scope 的解释方式。
- 启动器默认数据目录为仓库 `data/`，直接 CLI 默认 `~/.yunxi-bot`；部署应显式使用同一 `YUNXI_BOT_HOME`，否则会表现成“记忆丢了”。
- Task Budget 当前按外层 handler 调用扣减，步骤内工具循环可能发出多次实际模型请求，不能作为严格 HTTP 请求上限。
- daemon 的目标任务已改为每阶段刷新快照；长任务对其他回合的延迟、并行进程写台账和崩溃恢复，仍需要独立压力/故障测试。

## 6. 本轮完成的模型收敛

按用户明确要求移除 Agnes：运行模型表、CLI provider、密钥环境变量读取及自动远端回落都已取消。
移除 Agnes 时曾先接本地生成；随后按 D142 统一改用 DeepSeek，覆盖聊天、任务、摘要、画像提炼、主动陪伴表达和默认 think。Laya 决策保持独立，主动陪伴当前未启用。
历史 Agnes 费用表保留，仅用于旧台账重算。协议客户端更名为 `think/client.rs`。决策依据见 ADR D140。

以下是当时本地生成阶段的历史验证入口，当前轻量模式验收见上方链接：

```bash
python3 sidecar/e2e_local_auxiliary.py
python3 sidecar/e2e_local_task.py --output data/benchmarks/task-chain/after-agnes-removal.json
```

前者使用真实 Gemma 和固定的陪伴决策替身；后者使用真实 Gemma + Laya。两者顺序执行，用临时工作区和合成数据。
它们验证本轮接入与回归，不替代上述尚未接线能力的专项验收。

## 7. 后续重构应解决的具体问题

优先共用“运行环境装配”和“上下文组装”：把人格、用户画像、项目规则、按任务所需召回的记忆通过同一条明确接口提供给 chat、任务和守护入口。
目标任务现已按阶段刷新并记录指纹；其他入口尚待按实际需求统一。工具注册也应共用装配入口，同时继续按入口限制权限。

这些工作应保留现有任务状态机、审批、台账和模型进程边界。本轮知识库与语义向量新增能力采用 D141 的有界实现；扩大规模或迁移旧数据时再设计迁移链，不作目录重排。
