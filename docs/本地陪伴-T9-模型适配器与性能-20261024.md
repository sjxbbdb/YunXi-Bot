# 本地陪伴 T9：模型适配器与性能

状态：2026-10-24，已完成本轮基准与适配器收口。

## 适配器

- 本地陪伴：Qwen3.5-9B / Gemma 4 26B，按 `YUNXI_COMPANION_MODEL` 切换；默认 Gemma。
- 云端工作：默认 DeepSeek Flash；设置 `YUNXI_WORK_BASE_URL` + `YUNXI_WORK_MODEL` 可切任意 OpenAI 兼容端点，密钥读 `data/secrets/openai.key`。
- 自定义端点通过 `ModelSpec` 的 `openai-compatible` provider 走现有 `OpenAiThinker`，不需要改 Handler；能力/标签在 `ModelAdapter` 统一声明。
- 本地工具仍按模型能力挂载：Gemma 可用只读工具，Qwen fallback 不挂工具。

## 本机基准

脚本：`scripts/bench_companion_chain.py`，使用当前核心人格 + 画像 + local_chat 协议，测量加载/首轮/热轮；输出到 `data/benchmarks/companion-chain-*.json`。

机器：M2 Max 64GB，macOS 27.0.1；端口 17876；`max_tokens=48`，thinking 关闭。

| 模型 | 加载 | 首轮 | 热轮 | 首轮 prompt tokens |
|---|---:|---:|---:|---:|
| **Gemma 4 26B-A4B QAT 4bit** | **3.0s** | **11.47s** | **13.13s** | 6,078 |
| Qwen3.5-9B 4bit | 4.75s | 17.6s | 21.66s | 5,531 |

实际 chat-server 端到端受自动召回、工具轮次影响：T6 知识问答 6.2s，T7 工具调用 15.9s；均在本机完成，无云端。

## 决策

- **保留 Python MLX sidecar + Gemma 默认**：工具协议、人格/记忆/知识接入已验证；暂不为了“更快”替换成 mlx-serve/MTPLX。
- mlx-serve/MTPLX 仍是后续候选，但需要单独处理模型下载、工具协议、prompt cache 与服务生命周期；本轮不冒险换运行时。
- 自定义 OpenAI 兼容云端适配器只是配置入口，未对真实第三方端点做联网验收；启用前需自行配置密钥与隐私边界。

## 验证

- 适配器 metadata 单测通过。
- 基准脚本实跑 Gemma/Qwen，结果写入 `data/benchmarks/`。
- Rust：1470 passed / 0 failed / 39 ignored；clippy clean。
- App 重建成功。

## 已知限制

- 热轮仍 13.13s，说明当前 MLX 路径没有有效前缀复用；后续若引入 mlx-serve 的 prompt cache 才有明显改善。
- 自定义 OpenAI 兼容端点没有真实 API 集成测试。
- 本地工具调用多一轮，延迟高于自动召回。
