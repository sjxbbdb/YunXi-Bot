# 自主电脑操控录屏验收（2026-10-17）

状态：基础工具循环的自主操控证明已通过；真实出行尚不能宣称已自主到达付款页。无实际支付。

## 验收口径

用户要求火车票与酒店由Bot自行决定、操作，观察者仅启动、录屏、记录和转交真人的必要输入。沿用10月20日北京南至上海虹桥、一名成人、二等座，上海10月20日至21日一晚一间的场景；旅客由用户确认，具体身份不写入仓库。实际创建订单前仍须展示方案、金额、退改并获得真人确认。

使用显式忽略测试`recorded_travel::live_bot_travel`，复用正常`ChatHandler`、人格/画像/记忆取材、Laya路由、DeepSeek、图片工具循环及台账。注册电脑三工具、now、travel_prepare，禁止通过命令、文件、脚本、邮件等旁路代替界面操作。测试封装不编译进生产CLI和后台，不能把本次有限授权说成通用无人值守能力。

电脑动作由模型提出，观察者没有代点车站、车次、房型或订单按钮。录制的暂停、恢复，测试封装修补后的重启，以及用户登录/确认身份，必须分别列入桌面私有验收记录。失败片段、轮数上限和未录完整的片段不删除后冒充一次成功运行。

## 已暴露并修补的问题

- 模型可见的Driver参数原先要求`session`，适配器却禁止调用方提供它。先以失败测试复现，再从对外schema的properties/required中移除适配器管理字段，保留固定原始目录及实际调用时的拒绝与注入。全部35项契约均验证，不放宽未知参数。
- 原审批预览对浏览器ref未显示实际控件，只显示模型目的和参数。补充最新观察中匹配ref的真实角色、名称；未知ref不能借模型目的冒充已观察控件。已做失败先行的回归测试。
- 录屏预检中，系统`screencapture`限时结束能保存，中断长录屏却未正常保存。最终改用系统ScreenCaptureKit/AVFoundation的小型Swift录制器；READY后才允许操作，stdin结束正常封装MP4并校验时长、视频轨和无音轨。用户提前停止时录制器退出，后续动作检查转暂停。
- 测试授权封装最初误拒首次绑定的标签列表、合法前台参数以及车站候选。按实际Driver元数据补齐已审阅的查询范围；未知页面、任意坐标点击、协议/支付/提交等仍不自动放行。拒绝方向不改变。

- 前两次封装调试没有完整录像，不计为正式通过。
- 后续一段录屏因用户提前停止只保存约61秒，标为不完整。
- 第五次运行由Bot自主查到真实车次、选择G7并进入登录；真人登录期间暂停录制。恢复后Bot自行进入真实乘车人确认页，发现三位候选并向用户询问，没有擅选或提交。两个完整片段约116.94秒、65.36秒，均回读为2400×1638、单视频轨、无音轨。

第七次最终仍停在购票登录；主录像约107.86秒后中断，另录入9.32秒短暂小窗口，均不能作为全链路通过依据。随后将录制启动移至Driver成功验证窗口绑定之后，只有有活动录制的精确target/tab可动作，已结束的小窗口从录制目标中剔除。该录制封装修正已通过边界测试，尚未重新实测真实预订。

用户转而询问如何证明Bot具备电脑操控能力，因此补充了不受账户和库存影响的基础证明。复用已有`live_bot_browser_actions_and_deepseek_task`，仅在模型操作前后录制，排除模型运行前的合成页面初始化和后续脚本API检查。三次模型分别自主完成两次字段输入、一次点击和最终回读，独立重新读取页面验证目标；录像约17.55、18.56、17.11秒。后两次改变为运行时生成的合成姓名和另一目的地。最后一次在真实ThinkRequest入口统计到7次含截图请求，不从已经消费并脱敏的工具台账推断图片数，也不据此声称模型只用像素推理。

## 重现方式与界限

在本机macOS使用系统框架编译，不引入第三方运行时依赖，不重签现有原生助手：

```bash
swiftc -warnings-as-errors scripts/record_window.swift -o /tmp/yunxi-record-window
YUNXI_BOT_HOME='<现有数据目录>' \
YUNXI_RECORD_SCREEN=1 \
YUNXI_TEST_RECORDER=/tmp/yunxi-record-window \
YUNXI_RECORDED_TRAVEL_DIR='<尚不存在的桌面私有目录>' \
cargo test -p yunxi-bot-cli live_bot_travel -- --ignored --nocapture --test-threads=1
```

本人姓名和真人已经回复的信息可通过`YUNXI_TEST_PASSENGER`、`YUNXI_TEST_USER_MESSAGE`在可信启动端提供，绝不从页面自称获取授权，不把真实值写进仓库。账号登录、验证码、支付仍交真人；测试录像含个人页面，只保存在用户要求的桌面私有目录。

单次工具循环仍为32轮；仅测试驱动可在遇到该明确轮数错误时自动继续原目标，最多到第3轮对话，仍受每会话200次工具调用/1小时限制。其他失败、送达不明、登录或真人确认不自动重试。此续跑必须计入录像记录，不能说成生产后台已经具备持续自主预订。

测试程序正常退出只代表录制驱动结束，不代表旅行预订通过。仅到订单填写页、无库存、报价缺退改或需要人工接管时，均不得写“全流程通过”。

## 后续开发录屏规则更新

用户明确要求普通开发和回归不录屏，仅在明确要求某项能力的录屏验收时开启。当前忽略测试名为recorded_travel::live_bot_travel，默认不录屏；复现本报告历史录屏时必须显式设置YUNXI_RECORD_SCREEN=1及录制辅助程序。无该开关不启动辅助进程或生成mp4，窗口绑定与动作审批继续有效。已授权的日常Edge精确窗口可作为开发目标，不复制个人profile；首次浏览器接入设置及真实订单仍须实际验收。上述早期录像和通过数字属于对应历史版本，不代表新增真实预订通过。
