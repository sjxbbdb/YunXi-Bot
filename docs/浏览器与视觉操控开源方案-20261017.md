# 浏览器与视觉操控开源方案

核对日期：2026-10-17。目标是为云熙补充浏览器/电脑操控能力，先验证国内 12306 查票，再评估经批准创建待支付订单。本轮只阅读官方 GitHub README、接口说明和仓库元数据，没有安装、运行这些项目或接入真实账号。

同日进一步复核了关键源码，并新增国内旅行网页项目、官方酒店取消流程与 DeepSeek 官方适配的对照，见[电脑操控与国内出行源码评估](电脑操控与国内出行-开源实现评估-20261017.md)。

## 选型结论

**范围更新**：用户随后明确需要完整 Mac 电脑操控、票务、酒店三者。整体底座优先验证 Cua Driver 的原生与浏览器工具；下文 agent-browser 的优先级仅针对浏览器专项。完整评估见[源码与范围更新](电脑操控与国内出行-开源实现评估-20261017.md)。

优先验证 **vercel-labs/agent-browser**；**microsoft/playwright-mcp** 作为另一条接入路径。两者把浏览器作为执行工具，适合保留云熙现有的 DeepSeek 调度、Rust 审批和任务恢复。先采用页面元素/辅助功能快照，截图作为补充，避免为查网页重新常驻一个大型本地生成模型。

若后续需要跨 Mac 原生应用操作，再单独评估 Cua Driver；纯视觉参考 UI-TARS。这里的 trycua/cua 与当前聊天环境中的 cua_repl 名称相近，不代表它们是同一个实现。

## 候选比较

| 项目 | 已核实能力 | 对云熙的意义与限制 |
|---|---|---|
| [agent-browser](https://github.com/vercel-labs/agent-browser) | Rust CLI；辅助功能快照和元素引用、点击、填表、截图、会话保存；当前还提供 stdio MCP 和动作策略 | 首选执行底座。可以由现有模型逐步调用，不要求引入第二套 Agent；实际内存、协议兼容及12306可用性尚未测量 |
| [Playwright MCP](https://github.com/microsoft/playwright-mcp) | 微软维护的浏览器 MCP；默认用结构化辅助功能快照，元素操作不要求视觉模型；可开启 vision 能力 | 适合先接现有 stdio MCP 做查询验证。云熙 MCP 目前主要装配到 chat，不能因此声称 do/resume/daemon 也已接通 |
| [Browser Use](https://github.com/browser-use/browser-use) | Python 浏览器 Agent 库；可用本地或云端浏览器、自选模型、工具及结构化输出 | 功能完整，但整套引入要处理与云熙已有任务循环的职责重叠。当前 DeepSeek 端点及所选模型是否满足其调用协议需单独验证 |
| [Stagehand](https://github.com/browserbase/stagehand) | 浏览器 SDK，提供观察、操作、提取；有 TypeScript、Python、Go 接入 | 适合实现确定步骤与模型辅助相结合的网页工作流；要核实选用 SDK 的本地运行方式及模型调用成本 |
| [UI-TARS Desktop](https://github.com/bytedance/UI-TARS-desktop) | 截图识别、鼠标键盘操作，支持 Windows/MacOS/Browser，仓库还含 Agent TARS | 更贴近纯视觉电脑操控。需要合适的视觉模型；不应在没有必要时把整套桌面应用和本地视觉权重搬入当前轻量 Bot |
| [Cua Driver](https://github.com/trycua/cua) | 面向现有 macOS/Windows/Linux 机器的应用和浏览器控制，提供 CLI/MCP/SDK | 可参考 Mac 跨应用操作。Driver 与 Spaces/VM 是不同组件，后者不是本轮浏览器需求的前提。各平台及后台操作能力有明确边界 |

上述仓库在核对时均未标记为 archived；这只是维护状态信息，不能代替安全审计或12306适用性测试。

## 为什么先试 agent-browser

作者 README 提供了“快照取得引用 → 按引用点击/填表 → 再读页面”的工作方式，也提供页面变化比较、会话状态和动作确认机制。浏览器执行和模型推理可以分开，符合云熙当前结构。其 stdio MCP 可作为协议验证入口，CLI 也能通过限定参数的子进程调用；不需要先扩大 Rust 核心依赖。

这里的“优先”是架构匹配判断，不是性能实测结论。选定版本后仍要检查安装来源、实际命令与回执、浏览器来源、登录状态存储和更新方式。不能直接使用无限制 shell 或把整套任意 JavaScript 执行能力交给模型来换取接入速度。

## 接入时必须补上的业务边界

1. **工具权限**：查询、准备表单和提交订单分开。点击可能提交、取消或付款，不能把所有浏览器动作标成只读；框架的通用动作策略也不认识具体车票业务。
2. **批准绑定**：提交前从当前页面回读日期、区间、车次、席别、乘车人、票种、金额和备选规则。批准绑定这份内容及当前页面，变化后重新核对，不能仅批准一个“点击某引用”的动作就长期放行。
3. **失败恢复**：工具超时后先查询未完成订单；页面点击没有供应商幂等编号，不明时停止，不能自动再提交。进程重启和页面恢复也不等于交易状态已恢复。
4. **人工接管**：登录、验证码、人脸、短信和风控提示由用户处理；不启用绕过验证或高频刷票机制。
5. **业务回读**：区分排队、待支付、支付中和订单确认；订单创建成功、付款成功、日历同步成功分别报告，不能拿点击回执或模型文字代替实际状态。
6. **视觉接线**：云熙已通过 D152 完成用户显式附图与 DeepSeek 看图实测。工具输出目前仍只有文字，浏览器截图到模型的自动回传尚未接线；不能因执行器能截图就声称操作循环已能看图。
7. **隐私与提示注入**：网页文字不构成用户授权；截图只含任务页面，证件、验证码、Cookie 和支付链接不进入公开报告或普通工具日志。网页自称安全、只读或已获批准，均不能替代本地策略。

## 许可与费用

- agent-browser、Playwright MCP、UI-TARS Desktop 仓库标注 Apache-2.0；Browser Use、Stagehand 标注 MIT。具体再分发仍以所选版本、子目录和附带资产为准。
- Cua Driver 属于仓库的 MIT 部分，但 Cua Spaces 和 Driver Bench 等采用 FSL-1.1-MIT，某些可选感知组件还有独立许可，不能把整个仓库都按 MIT 引入。见[仓库许可说明](https://github.com/trycua/cua#license)。
- 开源软件可本地使用，不代表模型推理、云端浏览器和托管服务免费。首版优先本机浏览器、复用现有模型调用，实际成本与内存用专项测试记录。

## 建议验收顺序

先用合成网页测试读取、填表、定位失效、弹窗、超时恢复和审批拒绝；再在12306实际页面只读查票，核对日期、站点、车次、席别、价格和余票状态；然后验证用户登录后的提交前核对。只有单独授权的真实场景才验证创建订单，付款仍由用户完成。

本轮没有新增依赖、改变架构、登记工具、修改浏览器配置或执行真实查询/下单。通用项目存在不代表12306会始终接受自动化，页面改版、登录失效和风控仍可能要求人工处理。
