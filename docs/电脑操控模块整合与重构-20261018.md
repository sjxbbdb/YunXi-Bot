# 电脑操控与浏览器自动化整合

用户已明确允许综合开源实现，必要时重构整个电脑操控与浏览器自动化模块。本轮从实际失败出发，保留原审批、私有数据、固定Driver和真实订单边界，不新增运行依赖，不录屏，不重签已有原生应用，不替换常驻后台。

## 取舍

- **[Peekaboo](https://github.com/openclaw/Peekaboo/tree/93e64709dd74a0ff0e6ce6ec9221ddc19e3892a7)**：固定`93e64709dd74a0ff0e6ce6ec9221ddc19e3892a7`，MIT。实际读取`DialogService+Resolution.swift`、`DialogService+CGWindowResolution.swift`、`DialogDiscoveryTests.swift`及`docs/commands/dialog.md`。采用从父窗口结构识别Sheet、按精确控件处理、歧义拒绝、动作后核对的思路。云熙实测发现现有Cua也能从实际父窗口读到文件选择器的Cancel并执行成功，所以复用现有执行器，不引入另一套Swift运行时或自动关闭逻辑。
- **[Playwright](https://github.com/microsoft/playwright/tree/b335271cdc2b57cac2be8ad37c5dd283ac6b8938)**：固定`b335271cdc2b57cac2be8ad37c5dd283ac6b8938`，Apache-2.0。实际读取`packages/playwright-core/src/server/dom.ts`及`dialog.ts`的可操作性、遮挡核对和一次性处理实现，并参照官方actionability/filechooser文档。现有Cua已经有网页引用、dialog和set_input_files，不重复引入CDP执行器。发送、下单仍不能凭点击回执认定完成。
- **agent-browser / UI-TARS / browser-use / Travel Agent**：继续沿用[上一轮固定版本及许可](通用电脑操控补强-20261018.md)，分别借鉴引用有效期、截图尺度、状态停滞与人工接管。agent-browser默认自动接受部分网页弹窗不适用本项目，不迁移此默认行为。

## 改动范围

1. 拆开驱动契约/响应解析与工具编排，保持公开工具名和调用方式兼容，35项Driver操作不变。
   schema显式枚举已审核操作名，并区分观察与动作入口；browser_dialog在两个入口都保留，由inspect和accept/dismiss分别走原策略。验证层仍拒绝未知操作，不增加help/protocol别名或自动纠正动作。
2. 原生观察提供结构化弹窗上下文，限定实际父窗口的Sheet子树；无query的树截断导致按钮未读到时，未指定深度或上限大于5才做同一窗口最多2000节点、深度5、默认5秒的补读，不扩大较小深度/节点上限，保留显式超时限制。目录展开不会无限加大遍历预算；局部范围、字段摘要最多16项及其截断都明确标记。不能将子窗口图片与父窗口坐标混合，也不伪造capture_id。
3. 子窗口AX无法绑定时只给同进程窗口的下一步只读观察建议；不静默改动作目标。模型重新观察真实父窗口后，仍使用当前parent的实际AX token，走原逐次审批。活动Sheet存在时拒绝点击背景控件。
4. 将“当前仍有待用户选择的弹窗”保留在进程内；模型仅用自然语言结束时，通过现有ask_user正式挂起，而非假装任务完成。提问被拒或不可用时失败，不转成已完成；回答仍不构成动作批准。用户明确只查看/保留时不强求选择按钮，但多义弹窗仍通过ask_user交回控制，不能靠只读核验免除挂起。
5. 坐标继续使用原始截图像素与Driver变换，增加过期capture/越界等确定性检查；语义控件优先。未知弹窗、未保存和授权保留并追问。
6. 人工逐次批准的实际AXButton press有明确AX派发回执后，消费这一次选择；错误、疑似无效和未知回执不消费。再读到多义弹窗会重新等待。此举不认定界面效果或任务完成，仍须独立回读；核验工具和模型普通回复都不能消费选择。
7. 已观察到待选择原生弹窗后，不能换窗口或改用浏览器动作绕过；非该精确原生目标的电脑动作在审批前和派发前拒绝，并提示正式交还用户。未做全系统弹窗监视，不声称可以发现未观察的模态界面。

## 验证

先保留失败回归，再修公共路径。模型场景从7个扩展至8个，新增“只查看未保存提示并保留”；还检查网页弹窗及嵌套弹层、原生父窗口文件选择、三种尺寸坐标探针和普通网页/跨应用链路。合成目标与日志统一在`data/acceptance/`，正式追问和保留独立核对，不把审批挡住错误选择算作模型安全通过。网页prompt允许经过真实原生读取、输入及精确控件处理的有效路径，或browser_dialog专用路径；两者都须先读后处理并核对实际页面回调，不能只因选用了另一条有效路径判失败。

### 最终模型验收

同一轮8场景**严格8/8通过**，整体153.1秒。均为DeepSeek实际调用Bot的ToolRunner/ComputerTool、固定Cua Driver；外部只准备合成界面与核对回调，不替模型选择。保持24轮、8192 token上限、思考开启、温度0、同一通用协议；网页场景使用本轮同一隔离浏览器，其余逐项创建独立AppKit合成界面，串行执行。

补充回归：父窗口文件选择的默认预算及显式2000节点/深度25上限两种请求通过（14.0秒）；网页alert/confirm/prompt及嵌套HTML工具链通过（16.5秒）；三种尺寸、三个点位的**9/9坐标探针命中**（14.8秒，固定探针，不是模型视觉定位准确率）。通用跨应用模型任务**通过（83.3秒）**：填写网页、生成并核验实际预览、写入临时TextEdit文档、保存，再由测试进程直接回读UTF-8文件确认；同项还核对悬停、双击、右击、拖动、合成附件选择、下载回执和滚动。对应日志为`computer-refactor-live_*.log`。

原生工具链最终**通过（18.8秒）**：NSAlert取消/确认、Sheet取消、文件选择器经真实父窗口AX Cancel取消，独立回调逐项一致。日志`computer-refactor-native-completed.log`。早先文件选择器Escape路径有一次拒绝且未完成，保留失败日志；本轮使用已验证的AX路径，不将该键盘路径描述为已经修复。打开模态窗口也仍出现过“派发结果不明但窗口实际出现”的回执，测试先读取实际窗口，不重复打开。

### 迭代中保留的失败证据

- 最初7场景为6/7，文件选择器在24轮耗尽；后续合成诊断终止了两轮已确定重复读取的旧版本，未将其记作成功。
- 真实父窗口虽有AXSheet，但深度优先遍历展开目录耗尽节点预算，按钮没有返回。失败日志`computer-refactor-parent-budget-red.log`确认Cancel为0；补读后默认预算和显式2000节点两种请求都能读到真实Cancel，再由独立回调确认取消。
- 一轮网页prompt通过真实原生控件完成并回读，但旧测试只认可browser_dialog路线而误判；修正为验证实际读取顺序与页面结果。另一轮嵌套HTML被Edge自己的账户同步提示阻断，Bot停止并追问，未替用户确认。后续同组网页场景共用一份本轮新建的隔离浏览器，避免每项重建配置引入额外首次运行提示；仍不自动关闭这些提示。
- 后续一轮网页prompt在聚焦/键入/点击的原生长路径消耗24轮，尚未回读就耗尽预算；通用指引补充精确标签复用、先看schema及优先使用browser_dialog的完整流程，没有扩大测试轮数。另一轮模型把试验性的retain_dialog标志用于应追问的敏感授权，导致仅用普通文本询问。该例外已撤回；工具拒绝此未声明字段，只读核验不再清除挂起需求。
- 移除例外后的一轮8场景回归均有预期界面/接管结果，但文件选择已取消仍产生额外追问。追溯固定Driver的`platform-macos/src/tools/get_window_state.rs`发现elements_complete有意固定为false（AX投影与子节点读取不能证明全域不存在），不能用“不截断”替换成完整证明。修复为消费已经人工批准并派发的实际按钮选择，再观察仍有多义弹窗就重新等待；最终验收加上取消类场景不得额外ask_user的检查。没有用模型声明或只读标志跳过此限制。
- 严格检查后来确实抓到了多余追问：旧实现误读驱动内部的path字段，未识别最终输出。对照[固定Driver的ActionResult契约](https://github.com/trycua/cua/blob/6d6c734c127025fb39ad5d585a10382808b39dc1/libs/cua-driver/rust/crates/cua-driver-contract/src/outputs.rs)及实机回执，按规范读取route=accessibility和effect；旧path、未知值和suspected_noop均不消费选择。相关失败日志和修复前后单测保留，未以放宽验收来消除追问。
- 跨窗口读取也加入失败回归：新观察到另一弹窗不能覆盖先前未解决的选择，保留第一个待处理目标，不能用换目标再清空状态的方式绕过。

工程检查：`cargo fmt --all -- --check`、无warning的`cargo build`及`cargo clippy --all-targets -- -D warnings`通过。全量`cargo test -- --test-threads=1`为**1307项通过（CLI 97、core 1210），24项环境测试默认ignore**。默认并行全量回归两次碰到既有邮件测试的“另一个进程正在处理”锁竞争，失败日志保留在`computer-refactor-existing-mail-lock-failure*.log`，未改邮件生产逻辑或跳过失败测试；串行全量全部通过，不将其描述为并行问题已解决。

当前为本地开发改动，未推送、未替换常驻CLI、原生助理或Driver，未变更系统权限签名。原生真实授权、密码、验证码、真实交易支付、任意第三方应用和长时间无人值守可靠性不在本轮合成验收范围。窗口、布局及其他软件仍可能改变界面，现有进程内约束不等于OS隔离，参考源码和单轮成功也不等于通用成功率。
