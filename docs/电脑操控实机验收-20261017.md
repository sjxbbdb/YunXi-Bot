# Bot 电脑操控实机验收

本轮针对 Bot 自身的 `computer_schema → computer_observe → computer_act` 与 Rust `ToolRunner` 测试。CuaDriver 固定 0.36.0，使用本机已授予的辅助功能、屏幕录制权限。没有用 Codex 的浏览器操控替代 Bot 执行，也没有提交真实订单、邮件或付款。

## 测试范围和证据

| 场景 | 如何验证 |
| --- | --- |
| DeepSeek 自行操作网页 | 标准 Thinker、工具循环、截图/语义引用和策略门禁；模型查 schema、观察临时页面、分别填写中文姓名和目的地、点击生成预览，再回读确认 `计划预览：云熙测试员 / 杭州`。由测试程序另行读取实际页面断言结果，不能只依赖模型回答。 |
| 浏览器指针 | 悬停、双击、右击分别改变测试页的独立状态；拖动核验 pointer 起止坐标位移；滚动后回读原先在视口外的底部文字。使用显式 foreground 的可信输入路径。 |
| 文件选择与下载 | 只选择本轮生成、无个人信息的 UTF-8 合成附件；页面回读文件名。下载到本轮临时目录，检查落盘字节与固定样本完全一致，回执 `completed`、23 字节。没有上传用户文件。 |
| 原生文本编辑 | 仅操作新建的临时纯文本文件；定位精确窗口，前置、调整位置和尺寸并回读窗口边界，全选、输入中英文与数字、快捷键保存，核对磁盘 UTF-8 内容，再关闭并检查该窗口消失。 |
| 原生 AX 点击 | 指定计算器窗口，从最新 AX 树定位数字 7，点击后回读显示 7；再次使用同一 observation_id 被拒绝。先 Escape 清空测试计算器，保证可以重复运行。 |
| DeepSeek 视觉读取 | 另一次标准工具循环只给计算器截图，关闭 AX 树；模型读取并返回 7，不能通过 AX 文本取得数字。 |
| 失败路径 | 实机验证旧 observation_id 和其他 tab_id 在动作派发前被拒绝，旧观察拒绝后测试页仍未生成预览。普通回归另覆盖只读禁止动作、deny 优先、无法预先批准、跨窗口/进程、结构化拒绝与私有数据序列化。 |
| 系统只读接口 | 权限、屏幕尺寸、光标位置及剪贴板格式元数据均通过 Bot 适配器读取。剪贴板使用 include_text=false；没有读取正文或改写其内容。 |

模型任务在多次执行中耗时约 17–19 秒；实际延迟依赖网络、页面和模型，不能据此保证固定时延。测试动作逐次经过**仅存在于 ignore 测试中的审批器**，它只放行当前隔离标签的填写/点击，其余动作拒绝；测试中的工具包装也拒绝观察其他窗口。生产审批、`--yes` 限制和去重规则没有放宽。

窗口调整实测回读比请求存在 1–2 点偏差，验收允许 3 点误差，不承诺像素级布局精度；后续输入依据实际观察值定位。多文档应用前置时显式传 pid 和 window_id，不能只激活应用就认定目标文档取得焦点。

实机验收覆盖 21 种 Driver 操作（同一操作的不同手势不重复计数）：8 种观察 `check_permissions/list_apps/list_windows/get_window_state/get_screen_size/get_cursor_position/get_browser_state/clipboard_read`，13 种动作 `browser_prepare/browser_navigate/browser_type/browser_click/browser_pointer/browser_set_input_files/browser_download/bring_to_front/set_window_frame/hotkey/type_text/press_key/click`。这不代表全部 35 项或所有应用均已验收。

新增测试位于 `crates/yunxi-bot-core/src/tool/computer/live_acceptance.rs`。页面和 HTTP 服务只监听 127.0.0.1，使用 Driver 自有临时浏览器资料；临时文件和服务在退出时清理。正常 `cargo test` 不启动这些实机操作，也不访问 DeepSeek。会话序列化检查不含截图数据；界面原文/动作参数仍按 D153 在内存中处理。

测试中修正了验收准备和定位问题：core-only 测试未像 CLI 的 MeteredThinker 一样等待本地限流；重复运行计算器测试会把 7 追加到上一轮结果；原生前置只传 pid 在多文档时不能保证目标焦点，现已显式传窗口 ID，并使用每轮唯一文件名。没有改生产限流或放宽审批。

最终结果：5 项相关实机测试分别通过；`cargo fmt --all -- --check`、`cargo build`、`cargo clippy --all-targets -- -D warnings` 通过，`cargo test` 为 1242 通过、0 失败、17 项环境测试默认忽略。测试临时文档与浏览器窗口残留回读为 0。此轮只补充/修正验收与文档，未更改生产操控策略或重新签名原生助手。

## 重跑

只运行本地隔离网页和临时文本文件验收：

```bash
YUNXI_TEST_HOME="$PWD/data" cargo test -p yunxi-bot-core \
  tool::computer::live_acceptance -- --ignored --nocapture --test-threads=1
```

需要 DeepSeek 凭证已按现有方式保存在本机；此命令会发起真实模型请求。不要把密钥写进命令或报告。计算器的两项测试另需显式提供专用测试窗口的 `YUNXI_TEST_CALCULATOR_PID` 和 `YUNXI_TEST_CALCULATOR_WINDOW`，不能复用失效 PID；先通过窗口列表重新定位。

## 限制

未覆盖原生菜单、原生拖动/双击/右击、剪贴板写入及多格式恢复、浏览器 JavaScript 对话框、全部应用的输入兼容、休眠和多屏长期运行。真实票务/酒店的登录、库存和订单问题仍沿用[接入记录](电脑操控与国内出行接入-20261017.md)中的限制，本轮不扩大预订验收结论。
