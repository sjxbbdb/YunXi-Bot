# 本机Edge登录复用接入方案

用户希望直接使用本机日常Edge，而不再为旅行任务反复登录独立配置。当前接入的浏览器程序本来就是本机Edge，隔离的是用户配置。用户已明确批准该方案；代码与可信启动授权已配置，Bot已实际连接日常Edge并取得网页快照。

## 具体接入

- 保留现有Edge安装及日常配置，不复制Cookie、密码或profile，不用命令行远程调试参数重启日常浏览器。确认Edge进程、窗口以及需要使用的12306/携程标签；有多个配置或窗口时由用户选择，不猜。
- 复用Cua Driver既有`browser_prepare`的`strategy={kind:existing_profile}`和精确pid/window_id，由其验证窗口并处理浏览器的原生调试授权。本机Driver已保持standard并在可信启动端配置existing-profile授权，不能由模型工具调用自我提权；不能用普通MCP批准假装获得profile授权。
- Cua会获得该已登录配置的页面/存储访问能力，这比单看一个网页截图更宽。云熙仍只向模型提供本次精确绑定的目标页面，不能据此声称对整个Edge配置实现了OS沙箱或技术隔离。原图和界面私有信息沿用现有private_io处理；不保存Cookie/密码到项目、台账、state或配置。
- 查询、填写、结算核对和订单回读复用现有工具，已有登录有效时直接继续；网站过期或验证码交用户。下单/取消必须针对实际方案、总金额和条款逐次人工批准，付款由用户处理。模型、网页、截图中的“同意”都不能替代真人授权。
- 普通开发和回归默认不录屏，只有用户明确要求某项能力的录屏验收时开启；正常工具截图不是持续录像。独立命名配置保留为可选测试环境，不删除既有登录数据。

## 验收

先核对实际Edge页面登录状态，再验证跨对话复用同一配置，继而查询实际车次/房型、核对已选本人、生成待审批下单方案、提交后读取真实订单及付款页。不能把启动浏览器、看到用户头像或工具退出成功当作全链路通过。接入失败保留原浏览器并明确报告，不复制用户配置到隔离目录重试。

本方案涉及[AGENTS.md](../AGENTS.md)第6节“修改ADR中已确立的架构决策”先问人；批准前的[ADR D153](adr/0001-架构与边界.md)曾将现有已登录profile排除在接入范围。该切换及Driver新增授权已由用户明确确认后实施，ADR已同步更新。

## 当前实际进度

Driver 0.36.0原有签名/公证版本未变，macOS辅助功能与屏幕录制权限回读仍为true；没有重签云熙原生助手。本机新增com.yunxi.bot.computer登录启动器，仅用LaunchServices启动同一CuaDriver.app并传existing-profile授权，保留逐次工具审批。

已核对日常Edge的主进程和精确窗口，首次接入返回browser_wrong_target_refused；源码与实际回执表明当前UI无法找到其要求的New Tab控件。开发者仅预打开官方edge://inspect/#remote-debugging设置页，未代操作12306/携程网站。用户已勾选并允许浏览器确认；后续接入仍触发中文Edge确认，固定版本仅识别中文Chrome文案，无法自行完成。接入预检在同一已授权Edge窗口中取消旧的悬挂确认，并按原生AXSheet、完整Edge警告及三枚准确按钮核对连接确认；未修改或重签Driver、未复制Cookie或启动另一配置。其后Bot自己的browser_prepare成功、get_browser_state取得实际标签快照，并开始查询12306。

这证明本次运行及同一Driver下的会话连接可复用；尚未验证Edge/Driver重启后首次连接和长期登录。新连接再次出现浏览器确认时可能仍需用户处理，不能把已登录配置说成永不过期或永久免确认。真实创建订单和到付款页另计验收，不因接入成功标为通过。开发回归目录中没有录像或原图文件。

本轮Bot实际网站回读：12306显示未登录，携程跳转登录，已请用户在这份日常配置分别登录后继续。当前没有保存的本人资料可供选择，不能将连接成功说成登录复用已经跨重启通过。

## 携程登录后的回归

用户在同一日常Edge登录携程后，Bot的新会话实际回读已登录主页，未要求重复登录。尝试保留全部携程标签并另开12306时，暴露两处适配问题：验收封装未接受SDK等价的精确窗口target/default scope；绑定说明追加在JSON回执之后，破坏了验收程序的回执解析，导致窗口未登记。

已分别用失败测试复现：新建标签只接受同一已绑定窗口的一致定位，冲突定位、桌面目标、额外未知参数仍拒绝；绑定说明移至回执之前，保留观察ID首行和完整JSON尾部。失败尝试保留在桌面私有总结中，不计为新建标签或预订通过。修复后的实际页面结果另记，不由单元测试替代。

修复后实测窗口绑定登记正常；当前Edge的press_key/hotkey新建标签仍由Driver返回失败，重新观察未见新增标签，不计为键盘操作通过。Bot已改用同一精确窗口的原生菜单路径“文件→新建标签页”，并收到正常工具回执；还需以实际标签与目标网页确认结果，不能只凭动作回执标成功。没有更新或重签Driver。

最终新建标签实机结果：Bot自己调用原生“文件→新建标签页”，重新绑定并读取新标签，随后仅将该新标签导航至12306官方余票页，最后重新原生观察并bring_to_front。实际网页显示未登录；原两个携程标签未改动。当前等待用户登录12306；未选择乘客、未提交订单，也未进入付款页。观察者未代点网页。全部工程检查通过，cargo test为1258通过、18忽略、0失败；新版release已重载为running。

## 12306登录后的会话与查询修补

用户完成12306登录后，旧命名操控会话已在等待期间失效：窗口观察与列表均被拒绝。新客户端能正常列出原窗口，且Bot新会话回读12306已登录，并查询到真实车次。对固定Driver源码核查发现其会话空闲期限为5分钟：显式命名会话结束后保持失效，传输隐式会话在清理完成后可由同一所有者建立新生命周期，旧快照、引用与授权仍作废。

只读实机对照发现：隐式会话虽能列窗口/绑定，读取已登录配置的具体标签却被Driver以authorization_host_failed拒绝；同一管道下显式命名会话可正常读取。因此保留适配器管理的命名会话。超过5分钟未成功派发时，下次请求先使旧观察/核对失效、更换会话标识并明确返回degraded，原请求不派发；随后须重新原生观察、browser_prepare及绑定，不重放动作。已尝试订单记录保留，模型不能传session或提升权限，原120秒观察期限、锁和逐次审批不变。边界测试覆盖299/300秒与不反复更换。330秒仅窗口列表读取对照已完成：同一管道下旧命名会话读失败，隐式会话读成功；它只验证空闲生命周期，不代表隐式浏览器绑定可用。最终实现仍保留命名会话并显式退役重建。

同时补齐12306可点击座位的语义cell（与gridcell同属查询控件），提交/支付禁词和结算审批仍保留。携程标签导航此前被挡是因为没有先读取该目标标签，不放宽这条检查；后续要求先读目标的新快照。

会话与查询补丁的工程检查：cargo test共1259通过、18忽略、0失败，fmt、无警告build、严格clippy及release均通过。一次既有assistant临时目录并发测试失败，单项和默认全量重跑通过，未修改assistant业务代码。当前真实下单验收继续以Bot实机记录为准。
