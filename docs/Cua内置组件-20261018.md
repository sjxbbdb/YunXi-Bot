# Cua内置电脑组件

用户明确要求将Cua做成内置组件、随项目安装。云熙将固定0.36.0执行程序打包进`target/macos/云熙电脑组件.app`，通过上游官方embedded daemon协议作为直接子进程运行，不链接新Rust依赖、不增加第二套电脑工具执行入口。

## 安装和权限

`安装Mac环境.command`／`scripts/setup-macos.sh`已包含组件构建。已有环境只需运行：

```bash
python3 scripts/build-macos-computer.py
bash scripts/computer-component.sh authorize
```

为“云熙电脑组件”开启辅助功能、屏幕录制；如果系统未自动列出它，在对应设置页用“＋”选择上述应用。授权后完全退出组件再重新启动，避免进程缓存旧权限。邮件/日历使用的“云熙本机助理”没有重建或重签。

构建优先复用本机`/Applications/CuaDriver.app`，仅接受Apple签名团队YCK386LBJ7、bundle ID com.trycua.driver及版本0.36.0。未安装时下载官方固定发行包，SHA256为`2a83cf9c3a2fa7ae27f3fe62e426aeca5acf76511bb14dd64d10ccb2de6aecae`；校验失败停止，路径穿越、链接与特殊文件拒绝解包。不执行上游安装脚本，不安装模型、虚拟机、感知扩展，不要求用户另外安装Cua。构建采用暂存目录，完整验证后替换，并保留上一版；运行中的宿主拒绝被覆盖。

本机使用ad-hoc签名；更新组件可能需要重新授权。分发应使用稳定Developer ID（`YUNXI_SIGN_IDENTITY`），公证发行是另外的发布工作，当前不宣称已完成。原始上游二进制哈希、下载来源及许可证保存在组件Resources；二进制和用户状态不进Git。

## 运行和授权边界

- Bot连接前通过LaunchServices启动云熙宿主；宿主直接派生embedded Driver，保持真实的macOS权限归属。通信沿用MCP，固定私有socket，不回退外部Driver。连接时核实Driver报告的实际父应用身份，环境中的host标签不能单独通过校验。
- 宿主使用0700状态目录、单实例锁、私有socket、父进程存活管道。退出时停止子进程；意外退出后下一次连接可重新启动宿主，但不重放完成情况未知的动作。
- 子进程环境只保留必要系统字段，遥测和更新检查关闭；原始Driver输出不落盘。保持standard权限模式，未启用unrestricted或绕过审批。
- 日常浏览器profile授权独立保存，默认不开启。用户明确同意后运行`bash scripts/computer-component.sh allow-existing-profile`，下次启动生效；不是授权网站下单或付款。当前用户已有明确同意，本次迁移沿用该授权。
- `computer-component.sh start|stop|status|authorize`管理本机组件。电脑工具按需拉起；全新项目不会因此自动启用Bot后台、主动陪伴或无人值守电脑动作。已有后台配置在验收后迁移到新版程序。

官方依据：[嵌入协议](../third_party/cua/libs/cua-driver/rust/Skills/cua-driver/EMBEDDING.md)、[Swift示例](../third_party/cua/libs/cua-driver/rust/examples/embedded-host-macos/ExampleAgentHarness.swift)、[SDK生命周期实现](../third_party/cua/libs/cua-driver/rust/crates/cua-driver-sdk/src/embedded.rs)。保留Cua MIT及第三方声明，不把上游实现称为云熙原创。
