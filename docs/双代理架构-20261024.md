# 双代理架构（2026-10-24）

## 目标

把“陪伴”和“工作”拆成两个独立代理，而不是让一个聊天 Handler 同时承担两种职责：

- **陪伴代理**：本机 MLX 生成，聊天提示词，无工具，私密上下文不离开本机。
- **工作代理**：云端 DeepSeek 生成，职业任务提示词，带工具与审批，只接收任务正文。
- **任务分类器**：输入先经本地 Laya 判断聊天/任务，再决定走哪个代理。
- **模型适配器**：把“角色 → 模型 → 端点 → 能力”收在一处，不在 Handler 里散落模型名。

## 数据流

```text
用户输入
  ↓
TaskClassifier（Laya，本地；显式 /task /work /chat 优先）
  ├─ chat → 陪伴代理（本机 MLX，CHAT 协议，无工具，个人画像/记忆可用）
  └─ task → 工作代理（DeepSeek，WORK 协议，工具+审批，无个人画像/记忆）
```

工作代理启动时**不加载**画像、长期记忆和动态召回；从聊天切到任务时，只发送任务正文，不发送此前的私密聊天历史。工作代理自身有独立会话（`<session>-work`），不会反向污染陪伴上下文。

## 关键文件

- `crates/yunxi-bot-cli/src/model_adapter.rs`：陪伴/工作模型描述；`YUNXI_COMPANION_MODEL=qwen|gemma` 切换本机模型。
- `crates/yunxi-bot-cli/src/task_classifier.rs`：Laya 分类、显式指令、决策台账、`/task` 前缀剥离。
- `crates/yunxi-bot-cli/src/chat_handler.rs`：
  - `with_identity`：工作代理独立人格；
  - `with_chat_protocol`：工作/本机两套对话协议；
  - `without_personal_context`：工作代理不注入画像/记忆；
  - `route_for_spec`：由分类器强制指定模型，不再二次分类；
  - 本机聊天跳过二次审阅，避免多一次小模型调用。
- `crates/yunxi-bot-core/src/prompts/local_chat.md`：本机陪伴协议（无工具、直接回答）。
- `crates/yunxi-bot-core/src/prompts/work.md` + `work_persona.md`：职业任务协议与身份。
- `crates/yunxi-bot-cli/src/chat_server.rs`：双 Handler 装配、路由事件、独立工作会话、本机未启动的明确报错。
- `sidecar/mlx_backend.py`：本机 32k 上下文；`thinking=false` 且无工具时直接流正文；只有开启思考时才按思考协议解析。

## 运行

```bash
# 1. 本机陪伴模型（6GB 级；首次加载几十秒）
./启动本地模型.command

# 2. 聊天窗口或 chat-server
open target/macos/云熙聊天.app
# 或
YUNXI_BOT_HOME="$PWD/data" ./target/release/yunxi-bot chat-server

# 可选：本机换 Gemma 4 26B
YUNXI_COMPANION_MODEL=gemma ./启动本地模型.command
YUNXI_COMPANION_MODEL=gemma open target/macos/云熙聊天.app
```

本机模型未启动时，聊天直接报“本机模型未启动，这一轮没有上云”，**不会静默回落云端**。

## 当前验证

- 本地 Qwen3.5-9B：真实输入“你好”→ `route mode=chat / agent=companion / model=Qwen3.5-9B-4bit`，流式正文 + `reply` 成功；首轮约 52 秒（38k 字符人格/协议前缀的 prefill 成本）。
- 云端工作：`/task 用一句话说明 HTTP 是什么。`→ `mode=task / agent=work / model=deepseek-flash`，约 3 秒返回。
- 单测：分类器 3 项、适配器 2 项、双代理提示词/路由 2 项、核心提示词 2 项；Rust 全量测试与 clippy 通过；MLX 协议测试 11 项通过。

## 已知问题 / 下一步

1. 本机首轮 52 秒主要花在 38k 字符的前缀 prefill。下一步：本机专用短人格/短协议、prompt cache、或换 mlx-serve/MTPLX 做同机基准。
2. 工作代理尚未做正文级 PII 脱敏；“只发任务正文、不带历史/画像/记忆”是第一道边界，细粒度脱敏后续补。
3. 工作会话独立落盘但不自动恢复到 UI；当前 `--resume` 只恢复陪伴主会话。
4. 模型适配器目前覆盖本机 Qwen/Gemma + DeepSeek；任意 OpenAI 兼容市场模型的动态端点/密钥还在下一阶段。
5. UI 已能收到 `route` 的 `mode/agent/local` 字段，但尚未显示“本机/云端”徽章。
