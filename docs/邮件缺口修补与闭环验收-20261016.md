# 邮件缺口修补与闭环验收

本轮处理两项缺口：模型分析结果被协议校验拒绝，以及真实通知到日历、提醒事项的闭环复验。沿用 DeepSeek 只读分析、Laya 参考和原有通知策略，不执行邮件中的指令，不改变审批、调用预算、失败退避、台账或缓存格式。

## 修补内容

- 邮件审理请求单独启用 DeepSeek `response_format={"type":"json_object"}`；普通聊天、任务和会话摘要保持原输出方式。保留思考模式及 8192 token 上限。JSON 格式约束不能替代内容校验，也不能保证服务永不返回空结果。
- 通用审理提示词版本提升为 3。明确字符计数包含数字、拉丁字母、标点和空格；摘要建议 60–100 字符、行动建议 30–60 字符，为原有 160/100 硬上限留余量。显示文本必须单行，原文证据仍须逐字复制，不允许拼接、改写或自动截断。没有加入主题、发件人或特定请求的例外。
- 校验失败改为具体字段、长度或证据下标，不把模型原文或邮件正文写入错误原因。空结果与思考内容分开，不能拿思考过程当分析结果。错误仍进入待查看，未放宽检查或增加自动重试。
- 对话展示收件时间必须转换并注明本机时区；用户要求查询当前日历、待办时必须重新读系统记录，不能把历史写入回执冒充本轮查询。

协议格式依据：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode)。官方同时说明可能出现空结果，项目仍保留失败处理。
